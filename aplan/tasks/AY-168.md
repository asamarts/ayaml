## Why

`ayaml` runs one of the most thorough correctness and verification pipelines in the Rust YAML
ecosystem (zero `unsafe` in published crates, 899 Rust tests, 405 pinned YAML 1.2.2 Test Suite
cases with 0 deviations, RFC 8259 JSON differential oracle, 27 `proptest` suites scaling to 16,384
cases nightly, 10 structure-aware libFuzzer + ASan targets with encrypted crash artifacts, daily
Miri checks, 26 Kani bounded model-checking proofs, 16-shard `cargo-mutants`, process-isolated
adversarial DoS tests, deterministic allocation and Valgrind Callgrind gates, a daily scheduled-run
watchdog, and Trusted Publishing with SLSA build provenance), yet this assurance story is currently
scattered across short mentions in `docs/security.md`, `docs/tools.md`, and `docs/design.md`.
A dedicated `Correctness` page accessible directly from the top navigation bar makes the entire
verification architecture transparent and approachable to a junior generalist engineer.

## Scope

1. **Author `docs/correctness.md` (served at `/docs/correctness/`):**
   - Write in clear, natural, jargon-free English aimed at a junior generalist engineer (zero em
     dashes, zero marketing hype), explaining *what* each verification technique is, *what class of
     bug* it catches that earlier layers miss, *exact numbers and repository links* in `ayaml`, and
     *honest bounds* of what each layer proves.
   - Structure cleanly across 8 progressive layers with a compact "At a glance" summary table:
     1. Compile-time guarantees and static discipline (`#![forbid(unsafe_code)]`, `cargo-geiger`,
        panic-free production clippy profile, minimal dependency graph + scanner isolation, trait
        freeze, `cargo-semver-checks`, `public-api` diff, MSRV 1.88, `-Z minimal-versions`,
        Linux/macOS/Windows CI).
     2. Standards conformance and differential oracles (pinned SHA-256 YAML 1.2.2 Test Suite:
        405 cases / 2,240 default checks / 0 deviations; RFC 8259 differential oracle vs.
        `serde_json`; real-world LLVM/`stdarch` oracles; shared format vectors; forced event-stream
        equivalence `--cfg ayaml_typed_from_events`; `ayaml-edit` runtime self-verification).
     3. Unit, contract, state-machine fault injection, and child-process adversarial DoS tests
        (899 Rust tests, 61 doctests incl. 45 `book_doctests`, I/O short-write/interrupted injection,
        37 `in_child!` 1 GiB `RLIMIT_AS` adversarial tests).
     4. Property-based testing (`proptest` shrinking, custom YAML 1.2.2 grammar generator, 27
        properties scaling up to 16,384 cases nightly).
     5. Coverage-guided and structure-aware fuzzing (`libFuzzer` + AddressSanitizer across all 10
        fuzz targets, deterministic stable-Rust seed tests on every PR, `age`-encrypted crash
        artifacts).
     6. Undefined behavior detection with Miri (what UB and Stacked/Tree Borrows mean, daily bounded
        runs over `ayaml`, post-0.2.3 APIs, `ayaml-edit`, and the unpublished `memcount` allocator).
     7. Formal verification with Kani bounded model checking (contrasting testing with SAT/CBMC
        proofs, grouped walkthrough of all 26 `#[kani::proof]` harnesses across `ayaml` and
        `ayaml-edit`, plus `tools/run_kani.py` memory/time bounds).
     8. Testing the tests (`cargo-mutants` 16-shard weekly runs), deterministic allocation &
        Valgrind Callgrind regression gates, `scheduled-watch.yml` watchdog, and release
        supply-chain integrity (OIDC Trusted Publishing + SLSA build provenance).
   - Include authoritative external links explaining every advanced concept (Safe/Unsafe Rust &
     Rustonomicon, YAML 1.2.2 spec & Test Suite, RFC 8259, Proptest/property-based testing,
     LLVM libFuzzer, AddressSanitizer, Miri & UB Reference, Kani & CBMC bounded model checking,
     mutation testing / `cargo-mutants`, Valgrind Callgrind, SLSA provenance).
   - Cross-link cleanly to `security.md`, `limits.md`, `tools.md`, `stability.md`,
     `dependencies.md`, `compatibility.md`, and `benchmarks.md` without duplicating CLI cheat sheets.
2. **Wire top-level `Correctness` nav item and site/docs integration:**
   - Add `{ label: 'Correctness', href: `${BASE}/docs/correctness/` }` to `NAV_ITEMS` in

   - Add `Correctness` links in `SiteFooter.astro`, `DocsFooter.astro`, `docs/SUMMARY.md`,
