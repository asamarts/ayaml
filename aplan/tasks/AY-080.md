## Why

A release-window fuzz input showed a mode split: `[?!@!]` and a long handle after
`?` are accepted by default mode, while compat reports `undefined tag handle`.
The baseline also rejects the short form. The grammar needs one reviewed reading
before either reader changes, so the split does not become a silent compatibility
difference.

## Acceptance criteria

- [ ] decide from YAML 1.2.2 and libyaml whether `!@` after a flow `?` is a handle,
  a local tag, or an error, for `[?!@!]`, `[?!@66!]`, and a long handle
- [ ] make default and compat agree on the decided reading, or record the intended
  deliberate difference with a public rationale
- [ ] add a regression test covering the flow-question context and both modes
- [ ] conformance, hostile-input, and the existing tag tests stay unchanged or are
  justified; record the result in the changelog and compatibility notes
