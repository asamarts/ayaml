## Why

A release-window fuzz input showed a mode split: `[?!@!]` and a long handle after
`?` are accepted by default mode, while compat reports `undefined tag handle`.
The baseline also rejects the short form. The grammar needs one reviewed reading
before either reader changes, so the split does not become a silent compatibility
difference.

## Acceptance criteria

- [x] decide from YAML 1.2.2 and libyaml whether `!@` after a flow `?` is a handle,
  a local tag, or an error, for `[?!@!]`, `[?!@66!]`, and a long handle: `!@!` is a local tag
- [x] make compat match libyaml for the decided reading, while default keeps the
  YAML 1.2.2 plain-scalar reading documented in the compatibility notes
- [x] add a regression test covering the flow-question context and both modes
- [x] conformance, hostile-input, and the existing tag tests stay unchanged or are
  justified; record the result in the changelog and compatibility notes
