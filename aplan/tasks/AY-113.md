## Why

Issue #178 reports the peak heap of an untyped decode into a JSON tree, on nine generated
document shapes. The allocation gate measured other shapes, and its typed row decoded into
ayaml's own `Value`, a larger tree. The plan's figures for the issue came from that row, so they
never matched the issue's, and the work was steered by numbers that overstated the gap: by the
issue's measure eight of the nine shapes were already within its target.

## Acceptance criteria

- [x] the allocation counter generates the nine shapes and decodes each into a JSON tree through the compatibility reader with the count limits lifted, counting a reallocation by the bytes it adds
- [x] the method reproduced the issue's table at the commit the issue names, to the 0.1 MB it gives; that was measured outside the repository, and the table is in the issue's thread
- [x] `tools/json-alloc-corpus.tsv` budgets the peak, the allocation count, and the total bytes of each shape, at about 1.10 times the measured value, and the shape that is still over may not grow
- [x] the gate script checks the file and no longer passes over a budget file that is missing
- [x] `docs/benchmarks.md` gives the measurements and says what the earlier figures measured
