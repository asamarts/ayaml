## Why

Some position and indentation lookups scan back through the current line, and
some whitespace handling rescans, so cost can exceed linear time in line length.
Existing benchmarks use shapes that do not show it.

## Acceptance criteria

- [ ] scanning cost grows linearly with line length and whitespace-run length for flat flow, nested flow, quoted, and blank-heavy input, in both ASCII and multibyte text
- [ ] a scaling test fails on superlinear growth without being flaky on shared runners
- [ ] line and column results are unchanged, including CRLF, BOM, and multibyte input
- [ ] the performance gates still pass
