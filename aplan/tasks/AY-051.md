## Why

Conventions in prose drift, so ayaml and adotenv should prove they agree on positions and
edit ordering without either taking a dependency on the other. adotenv has published the shared
test vectors under its `tests/vectors/`, so this no longer waits for them.

A first comparison of `LineIndex` with the ten position cases, in each of the three encodings,
found the same answer at 23 of 30 once lines and columns are counted from one, as here, and a
leading byte-order mark is left out of the columns, which the vectors give as `without_bom`.
The rest differ in three ways. An offset inside a character has a UTF-8 column there and is an
error here. An offset between the CR and the LF of one line break is an error there and a
position here. And an offset inside the byte-order mark that the columns leave out is column 0
there and an error here. `PositionError` can gain a variant without a break, but each of these
changes what a call returns, so they are looked at before 0.2.0 is tagged (AY-121).

## Acceptance criteria

- [ ] the position and edit-order vectors and the report schema are vendored with a recorded source and hash
- [ ] a test runs ayaml against the vectors, and any stated exception is listed and reviewed
- [ ] CI fails if the vendored files do not match the recorded hash
- [ ] a page states what ayaml offers at each interface layer today
