## Why

Conventions in prose drift, so ayaml and adotenv should prove they agree on positions and
edit ordering without either taking a dependency on the other. adotenv has published the shared
test vectors under its `tests/vectors/`, so this no longer waits for them.

A first comparison of `LineIndex` with the ten position cases, in each of the three encodings,
found the same answer at 23 of 30 once lines and columns are counted from one, as here, and a
leading byte-order mark is left out of the columns, which the vectors give as `without_bom`.
The rest differ in three ways. An offset inside a character has a UTF-8 column there and is an
error here. An offset between the CR and the LF of one line break is an error there and a
position here. And an offset inside the byte-order mark that the columns leave out is column 0
there and an error here. `PositionError` can gain a variant without a break, but each of these
changes what a call returns.

The owner decided on 2026-11-19 to take all three answers from the vectors, and to give the index
the contract's names and numbers while no release has it: `to_position` and `to_offset`,
zero-based positions with a one-based `Location` beside them, an index that borrows its input,
and the contract's four reasons in `PositionError` (D96).

## Acceptance criteria

- [x] the position and edit-order vectors and the report schemas are vendored with a recorded source, and the digest of each is recorded in the check suite; the set's own manifest of digests is left out, since the secret scanner takes a line of it for a key
- [x] a test runs ayaml against the vectors, and any stated exception is listed and reviewed: every position case passes in each encoding, and the one form the index doesn't offer, a leading mark's bytes as columns, is stated in the test and in `tests/vectors/SOURCE.md`
- [x] CI fails if the vendored files do not match the recorded hash
- [x] a page states what ayaml offers at each interface layer today
- [x] `LineIndex` has the contract's names and rules: `new` borrows the input, `to_position` gives a zero-based position, `to_offset` converts back, and `PositionError` has the four reasons by the names that the vectors and adotenv give them
- [x] the columns leave out one byte-order mark that opens the input, and no other mark, as adotenv's index and an editor count: the two indexes give the same answer on 200,000 generated texts, which the 30 vectors don't decide
- [x] `Location` is the one-based display type that `Error::location()` returns, as in 0.1.3, and a position converts to it
- [x] every offset and every position of every short text of line breaks, marks, and characters of each width converts as the text alone says
- [x] a reader's error stands where the index puts its span on every line that begins with no mark, and as many columns from it as a stated rule says on a line that begins with one, which a test holds every reader to on every short text
