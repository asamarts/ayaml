## Why

The docs say limits fail closed, but some costs have no limit, and some settings
turn a limit off. Peak memory for scalars and token storage also deserves a stated
bound.

## Acceptance criteria

- [x] total tag expansion is bounded, with a structured limit error
- [x] settings that would disable a budget are rejected. A `node_cost_bytes` of 0 made a copied collection of empty nodes free, and every entry point that takes limits now refuses it. Every other limit is a ceiling, where 0 refuses more and the largest value is an explicit choice
- [x] block-scalar and arena peak memory is measured and bounded relative to input. A block scalar is built as it is read, and a read of one holds at most 8 to 16 times its input in the tests, by its shape; the old listing of lines held 25 to 42 times. The line index is allocated once, at 8 bytes for each CR or LF. The token arena holds about 100 bytes a token, every token counts against `max_events`, and its growth copies linearly with at most a sixteenth unused
- [x] each bound has tests below, at, and above it, under a memory cap: tag expansion, the least node cost, and a block scalar's size, on every entry point that takes limits, in children with an address-space limit. The memory bounds are measured in a child of their own for each read. AY-034 covers the other limits
- [x] the linear-time test can fail on a quadratic scan whose longest run stays under its quick threshold: both linear-time tests repeat a quick run until its batch takes the threshold, and a synthetic quadratic scan that runs in a few milliseconds fails the shared check
