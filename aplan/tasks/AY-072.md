## Why

The repository has strong semantic gates but no declarative check for repository shape,
portable filenames, text hygiene, or source-file growth. alint 0.22.0 supplies those checks,
inline GitHub annotations, and an offline bundled-ruleset model. Turning the final 2,000-line
rule on immediately would fail five existing files, so the first green change needs explicit,
visible non-growth ratchets rather than a broad baseline.

## Acceptance criteria

- [x] `.alint.yml` requires alint 0.22.0 and extends the bundled `oss-baseline`, `rust`, `ci/github-actions`, `hygiene/no-tracked-artifacts`, `tooling/editorconfig`, `agent-hygiene`, and `agent-context` v1 rulesets
- [x] every deterministic error and warning is blocking; advisory infos such as CODEOWNERS, a code of conduct, and one pinned Rust toolchain stay non-blocking
- [x] full-tree checks enforce workflow names and immutable action references, least-privilege workflow tokens, final newlines, trailing whitespace, portable names, no symlinks or submodules, tracked-artifact hygiene, `.editorconfig`, and line-ending normalization
- [x] `.editorconfig` declares UTF-8, LF, a final newline, trailing-whitespace removal, four-space Rust and Python indentation, two-space YAML indentation, and tab-indented make recipes; `editorconfig_conforms` covers `.aplan.yml` and maintained files under `.github/`, while rustfmt owns Rust indentation and byte-exact parser fixtures and fuzz corpora remain outside content-conformance rules
- [x] the pinned upstream YAML suite's intentional `README.md` / `ReadMe.md` collision is excluded only from the case-conflict rule, not ignored by alint as a whole
- [x] one error-level `file_max_lines` rule with `expect_matches: true` covers every maintained `.rs`, `.py`, `.sh`, and `.bash` file plus `tools/hooks/*`, with `max_lines: 2000`
- [x] only `scanner.rs`, `parser.rs`, `emitter.rs`, `tests/regressions.rs`, and `tests/contracts.rs` are temporarily excluded from that rule, and an error-level rule caps each at its starting line count so none can grow
- [x] no alint baseline is committed; the current tree passes after the explicit ratchets and `.editorconfig` are present
- [x] throwaway boundary probes prove that 2,000 lines pass and 2,001 lines fail for every covered extension, the extensionless hook, and a Rust source outside the current `crates/`, `fuzz/`, and `tools/` layout
- [x] the official alint Action is pinned to the v0.22.0 commit `8d7a60f6642cb1b59537202ae81df7d951a078ad` and runs the full tree with `fail-on-warning` in its own required branch-protection job; local CI requires the matching binary, and a missing or mismatched binary fails release mode rather than silently passing
- [x] `tools/ci-local.sh` and its sync tests cover the new job, and CONTRIBUTING documents installation, the local command, the version-update procedure, and why `--changed` is not the gate
- [x] a repository-lint decision record fixes the bundled rulesets, strict-warning policy, staged size ratchets, upstream-suite exception, EditorConfig enforcement scope, and version-pinning policy
