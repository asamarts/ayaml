## Why

The repository has strong semantic gates but no declarative check for repository shape,
portable filenames, text hygiene, or source-file growth. alint 0.22.0 supplies those checks,
inline GitHub annotations, and an offline bundled-ruleset model. Turning the final 2,000-line
rule on immediately would fail five existing files, so the first green change needs explicit,
visible non-growth ratchets rather than a broad baseline.

## Acceptance criteria

- [ ] `.alint.yml` requires alint 0.22.0 and extends the bundled `oss-baseline`, `rust`, `ci/github-actions`, `hygiene/no-tracked-artifacts`, `tooling/editorconfig`, `agent-hygiene`, and `agent-context` v1 rulesets
- [ ] every deterministic error and warning is blocking; advisory infos such as CODEOWNERS, a code of conduct, and one pinned Rust toolchain stay non-blocking
- [ ] full-tree checks enforce workflow names and immutable action references, least-privilege workflow tokens, final newlines, trailing whitespace, portable names, no symlinks or submodules, tracked-artifact hygiene, `.editorconfig`, and line-ending normalization
- [ ] `.editorconfig` declares UTF-8, LF, a final newline, trailing-whitespace removal, four-space Rust and Python indentation, two-space YAML indentation, and tab-indented make recipes; `editorconfig_conforms` enforces maintained YAML, while rustfmt owns Rust indentation and byte-exact parser fixtures and fuzz corpora are excluded
- [ ] the pinned upstream YAML suite's intentional `README.md` / `ReadMe.md` collision is excluded only from the case-conflict rule, not ignored by alint as a whole
- [ ] one error-level `file_max_lines` rule with `expect_matches: true` covers every maintained Rust, Python, shell, and hook source file, with `max_lines: 2000`
- [ ] only `scanner.rs`, `parser.rs`, `emitter.rs`, `tests/regressions.rs`, and `tests/contracts.rs` are temporarily excluded from that rule, and an error-level rule caps each at its starting line count so none can grow
- [ ] no alint baseline is committed; the current tree passes after the explicit ratchets and `.editorconfig` are present
- [ ] the official alint Action is pinned to the v0.22.0 commit SHA and runs the full tree with `fail-on-warning` in its own required branch-protection job; local CI requires the matching binary, and a missing or mismatched binary fails release mode rather than silently passing
- [ ] `tools/ci-local.sh` and its sync tests cover the new job, and CONTRIBUTING documents installation, the local command, the version-update procedure, and why `--changed` is not the gate
- [ ] a repository-lint decision record fixes the bundled rulesets, strict-warning policy, staged size ratchets, upstream-suite exception, EditorConfig enforcement scope, and version-pinning policy
