## Why

YAML 1.2.2 is specified as a strict superset of JSON (RFC 8259). Comparing
`ayaml` directly against `serde_json` on a comprehensive JSON conformance corpus
provides a zero-cost, independent oracle in CI covering flow collections, Unicode
escapes, surrogate pairs, number syntax, whitespace, and edge-case quoting.

## Acceptance criteria

- [x] a deterministic RFC 8259 JSON conformance test suite runs in `cargo test` comparing `ayaml::parse_value` and `ayaml::from_str::<serde_json::Value>` against `serde_json::from_str`
- [x] valid JSON inputs parse to identical values across `ayaml` and `serde_json`, including Unicode escapes, extreme numbers, and nested flow structures (with RFC 8259 UTF-16 surrogate-pair escapes `\uD834\uDD1E` vs. YAML 1.2.2 §5.7 `\UXXXXXXXX` documented and asserted as an intentional boundary)
- [x] any intentional YAML 1.2.2 versus JSON boundary case (such as duplicate keys, integer width, UTF-16 surrogate-pair escapes, `-0`, overflowing floats, leading zeros, trailing commas, leading BOM, and unescaped tabs) is explicitly documented and asserted
