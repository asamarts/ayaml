## Why

`tests/regressions.rs` is 3,632 lines and `tests/contracts.rs` is 2,182. Keeping unrelated
contract and regression families in one integration-test crate file makes review and ownership
harder, while creating many top-level integration crates would needlessly increase compile work.

## Acceptance criteria

- [ ] each top-level integration-test crate becomes a thin module root with concern-based child modules rather than many new top-level test crates
- [ ] every resulting file is at most 2,000 lines, and both test exclusions and temporary ratchets leave `.alint.yml`
- [ ] assertions and covered behavior are not weakened, duplicated, or replaced by wiring tests; only imports, helper visibility, and module organization change
- [ ] the listed test inventory does not lose a test, all prior tests still execute, and `aplan verify` resolves every existing test evidence reference after any qualified-name change
- [ ] bounded default/all-feature and adversarial test runs pass
