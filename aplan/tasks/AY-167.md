## Why

`site/src/pages/benchmarks.astro` currently uses tall, linear CSS `div.bar-row` strips without
axes, reference baselines, or legends, and shows only parse time in the primary Tier 1 and Tier 2
bars (while peak heap and allocation counts sit buried in wide numeric tables or tiny muted
subtitles). Linear bars also let outliers such as `libfyaml doc` (5.63x) squash the top entries
into the left edge of the chart. Build-time inline SVG charts computed directly from the pinned
JSONL files make both CPU/time and memory comparisons immediately readable while actually reducing
total page height and shipping zero additional runtime JavaScript.

## Scope

1. **Build zero-JS, theme-native, accessible inline SVG chart components under `site/src/components/charts/`:**
   - `DivergingRatioChart.astro`: horizontal log2 ratio chart centered on a `1.00x (ayaml)` vertical
     spine (`0.25x` to `8x` ticks) so faster C++ arenas extend left and slower peers extend right
     without outlier squashing. Wire existing `[data-tabs]` in `#tier2` and `#tier1` across
     **Parse time | Peak heap | Allocations** so readers compare both CPU and memory in the same
     vertical footprint; reuse the Tier 2 chart in `index.astro`'s benchmark snapshot.
   - `DualMetricBarChart.astro`: paired two-column horizontal bar chart in `#typed` showing
     **Throughput (MiB/s)** alongside **Peak heap (KiB)** + allocation badge on a shared `0-150 KiB`
     peak scale across the 3 scenario tabs (`frontmatter-tiny`, `Below 4 KiB`, `Above 4 KiB`) so
     the 39% streaming heap drop at 4 KiB and 7.5x `yaml-serde` memory savings are immediately visible.
   - `GroupedBarChart.astro`: single unified grouped horizontal bar chart (`0-260 MiB/s`) replacing
     the 3 separate stacked `.emit-card` blocks in `#emit`.
   - `SpeedupBulletChart.astro`: baseline-anchored (`1.0x`) lollipop/range-bar chart in `#progress`
     comparing `v0.2.3` to current throughput alongside peak-heap reduction chips.
   - `ScalingPlot.astro`: compact two-panel SVG (~230px tall) in `#scaling`: left panel log-log
     Peak Heap vs. Input Size (`10 KiB -> 100 KiB -> 1 MiB`) with an `O(n)` slope guide; right panel
     normalized 10x step-ratio plot relative to `1.00x` ideal linearity, paired with a tightened
     3-row family summary table.
   - `ScenarioDotStrip.astro`: optional/tabbed **"Visual map"** tab inside `#matrix` (zero added
     page height) plotting all 23 timed scenarios normalized to `ayaml value = 1.00x` on a log2
     axis across key peers.
2. **Keep `docs/benchmarks.md` concise and well-linked:**
   - Keep `docs/benchmarks.md` clean pure Markdown (preserving `markdownlint`, GitHub rendering,
     `book_doctests`, and `llms-full.txt`) and add a clear top callout linking directly to the
     visual charts at `https://asamarts.github.io/ayaml/benchmarks/`.
3. **Verify layout, theme parity, accessibility, and SVG integrity:**
   - Use CSS custom properties from `tokens.css` so every chart renders cleanly in both light and
     dark modes with crisp `tabular-nums` alignment and responsive mobile scaling.
   - Give every chart `<figure>`, `<svg role="img" aria-labelledby="...">`, `<title>`, and `<desc>`
     with accessible tabular data preserved.
   - Add automated checks in `site/scripts/check-links.mjs` / `test-scripts.mjs` verifying rendered
     SVG charts contain no `NaN`/`Infinity` attributes and include accessible labels.
