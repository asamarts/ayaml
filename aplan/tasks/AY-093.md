## Why

Issue #164: `Mapping::get_str`, `get_str_mut`, and the generic lookup methods built a new
`Value::String` for every borrowed string key.

## Acceptance criteria

- [x] `get_str`, `get_str_mut`, `get`, `get_mut`, and `contains_key` accept `&str` without
      constructing a `String`
- [x] borrowed lookups hash and compare exactly as `Value::String` keys do
- [x] remove and shift-remove use the same borrowed key path
- [x] the lookup result and mapping order are unchanged
