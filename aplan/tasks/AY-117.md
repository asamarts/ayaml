## Why

Independent reviews of the reader of events (AY-104) and of the second audit's fixes (AY-114)
found resource costs that the reader's documents denied, four node spans that ran past their
node, a compatibility reading that depended on how many byte-order marks opened the stream,
gate tests that passed with the gate broken, and statements in the changelog and the docs that
were wrong or missing for a reader coming from 0.1.3.

## Acceptance criteria

- [x] a reader that takes events as it needs them is handed a document's directives a few at a time, so no event waits for each directive of a long run
- [x] a root that is built whole is built with room for the entries the parser counted, and read with the tokens freed: a root with an anchor, with a tag that it keeps, or that an enum reads peaks as a read that builds the tree first
- [x] a refused input is scanned at most twice, and the path that kept an input of 4 to 8 KiB in chunks is gone
- [x] `Value` and `Mapping` give back the room that growing without a size leaves spare, so a value read from events keeps no more than one that was told each size, and a root flow collection tells its visitor its size
- [x] with duplicate keys refused, a key takes 24 bytes in the set of its mapping's keys, where it took a node's 80
- [x] the budgets of the untyped decode hold a root with an anchor in each style, a document of anchored nodes, and a run of directives, and the typed budget's peak is lowered to what is measured
- [x] the limits document, D91, D95, the design note, and the benchmarks say what a refusal costs, that a target has read what stands before a fault, what a target is told of a collection's size, and what a document of anchored nodes costs
- [x] a mapping with an alias among its keys gives no lookup and no entry span, a pair in a flow sequence ends with the last thing it writes whatever its key is, and in an input with a byte-order mark past its start a missing value stays where the parser places it
- [x] in compatibility mode a run of byte-order marks at the start of the stream reads as one mark does: a comment may follow it, and a document marker after it is text one column in
- [x] a span whose end is before its start is empty, and asking for its length doesn't overflow
- [x] the allocation gate's tests run it on three budget files of their own and see each row it checks, so they fail when any one file is passed over; the policy test requires the step that runs the gate to have no condition
- [x] the timing test of nested keys refuses a read that fails, and uses a key wide enough in an optimized build that hashing it at every level goes past the bound
- [x] tests that a review wrote to kill surviving single changes are in: a mapping's visitor that stops early or asks on after a fault, an entry refused unread, a value asked for before a key, and runs long enough that the grammar stops inside them
- [x] the changelog marks each breaking change with what a caller changes, lists the differences from 0.1.3 that it left out, and no longer describes states that no release had
- [x] the release procedure lists every place that repeats the version, and a policy test fails while one of them disagrees with the workspace
- [x] what is left is filed: sizes for collections read from events (AY-118), a document of mostly anchored nodes (AY-119), and generated span documents that reach each rule (AY-116)
