## Why

Documentation tools, task trackers, and static site generators commonly embed a
leading YAML document delimited by `---` and `---` (or `...`) ahead of arbitrary
non-YAML body text. Parsing the full file fails on the trailing body, forcing
each consumer to re-implement error-prone line splitting that can drift on BOMs,
CRLF endings, quoted `---` lines inside block scalars, and byte offsets.

## Acceptance criteria

- [x] a public frontmatter/prefix helper parses or splits a leading YAML document and returns the remaining body slice with its exact byte offset into the original input
- [x] leading BOM, LF/CRLF line endings, block scalars containing `---` lines, empty frontmatter, missing closing delimiters, and resource limits are handled accurately
- [x] unit and property tests verify round-tripping, span offset alignment with `LineIndex`, and adversarial limit enforcement
