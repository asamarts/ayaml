## Why

Wall-clock timings cannot reliably isolate small performance wins or catch gradual regressions
on shared machines, and maintaining a separate hand-written instruction probe drifts away from
the real benchmark suite (for example, missing `depth-64`, `large-scalar-1mb`, and post-0.2.3
APIs). Similarly, a single aggregate allocation counter shows *that* peak heap or allocation
count is high, not *which call site* caused it.

Running deterministic Valgrind Callgrind (instructions, simulated cache misses, branch
mispredicts, and per-function attribution) and Valgrind DHAT (per-call-site `at-t-gmax` peak
heap, allocation count, and total bytes) directly over the workspace's unmodified Criterion
benchmarks gives reproducible, load-immune bottleneck identification throughout the pre-1.0
optimization cycle and prevents multi-PR sliding-window creep.

## Scope

1. **Criterion counting shim in `crates/xtask` (`cargo xtask det`):**
   - Add a lightweight counting stand-in for `criterion` (patched via
     `--config patch.crates-io.criterion.path=...`) with an `#[inline(never)]` measurement
     boundary so Valgrind Callgrind collects exclusively inside steady-state iterations
     (`--collect-atstart=no --toggle-collect=*__ayaml_det_measure* --cache-sim=yes --branch-sim=yes`),
     computing exact per-iteration `Ir`, `EstimatedCycles`, data/instruction cache misses, and branch
     mispredicts via `(counts(K2) - counts(K1)) / (K2 - K1)` over the standard Criterion `ayaml-bench`
     benchmarks.
   - Support comparing `--base REF` and a pinned long-horizon `--anchor REF` so multi-PR creep
     cannot accumulate unseen.
2. **Deterministic hotspot & allocation-site profiler (`cargo xtask profile`):**
   - Add a `callgrind` subcommand that runs `callgrind_annotate --inclusive=yes` and emits a
     ranked per-function self/inclusive `Ir`, cache-miss, and branch-miss table (and optional
     diff against `--base REF`).
   - Add a `dhat` subcommand that runs Valgrind DHAT (`--tool=dhat`) on selected fixtures and
     modes, parses the DHAT JSON (filtering fixture setup), and prints the top call sites by
     at-peak (`at-t-gmax`) bytes, allocation count, and total allocated bytes.
3. **Document local profiling workflow:** Update `docs/tools.md` and `docs/benchmarks.md` with
   concise usage commands for `cargo xtask det` and `cargo xtask profile`.

## Acceptance criteria

- [x] `cargo xtask det --suite pr` measures steady-state `Ir` and `EstimatedCycles` directly on `ayaml-bench` benchmarks with deterministic repeatability (< 0.1% run-to-run drift)
- [x] `cargo xtask profile --tool callgrind` and `cargo xtask profile --tool dhat` output exact top functions and top peak-heap/allocation-count call sites with fixture generation excluded
- [x] `--anchor` comparison is supported and unit-tested in `crates/xtask`
- [x] `cargo test -p xtask --locked` and `tools/check_docs.py` pass cleanly
