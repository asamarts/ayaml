## Why

Every tag written with a handle holds its own copy of the prefix that handle stands for, and no
limit counted those copies. One long `%TAG` prefix and many short tags could use memory far beyond
the input: about 1 MiB of input could reach 2 GiB. The address-space bound stopped it in a test,
but a program with no such bound would run out of memory. All published releases do this.

## Acceptance criteria

- [x] each use of a tag handle counts its whole prefix against a limit, across a stream
- [x] the limit applies to `%TAG` handles, the built-in handles, and a handle that expands to a core name
- [x] every entry point returns a limit error with a span, inside the hostile-test bounds
- [x] the limit has tests below, at, and above its ceiling
- [x] the default leaves room for ordinary documents
- [x] `docs/limits.md` and the changelog state the limit
