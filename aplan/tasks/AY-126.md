## Why

An audit of the 0.2.0 tag before publishing found five concrete gaps:

- `EventCursor` extended an empty queue with the parser's over-reserved event vector, holding
  events twice during the copy and retaining unused capacity while a reader built values from them.
- On an input over 4 KiB read from events, a root enum target that swallows deserialization errors
  could mask a trailing document or post-root syntax error, because `Stream::build_root` did not
  record `self.end()` failures as document faults.
- The event writer refused directives that `compat::parse_events*` accepts when a trailing comment
  contains a byte order mark, and refused an untagged, unanchored empty plain scalar in a flow
  sequence (as produced after dropping a mismatched core collection tag such as `[!!map ]`),
  breaking the `emit` fuzz invariant.
- The event writer emitted long alias keys as implicit mapping keys without checking
  `MAX_IMPLICIT_KEY_CHARS`, producing output past the 1,024-character limit that no reader loads.
- `tools/check_deps.py` missed target-specific runtime dependencies and non-plain scanner imports,
  and `repository_policy` did not reject a `needs` clause on a required CI gate job.

## Acceptance criteria

- [x] `EventCursor` shrinks its loaded chunk and moves it into `VecDeque` without copying or keeping unused capacity
- [x] a root enum target that swallows errors still fails on trailing documents and post-root syntax errors on every typed read path and input size
- [x] the event writers round-trip compatibility directives with a byte order mark in a trailing comment while still refusing one outside comments
- [x] the event writers emit `~` for an untagged, unanchored empty plain scalar inside a flow sequence (such as `[!!map ]`), round-tripping in both modes
- [x] the event writers use explicit `?` keys for alias keys longer than `MAX_IMPLICIT_KEY_CHARS` in both block and flow mappings
- [x] `tools/check_deps.py` catches target-specific direct and cross-target transitive dependencies, visibility/attribute-prefixed `use`, inline disallowed paths, and new scanner submodules, and `repository_policy` rejects `needs` on gated CI jobs
