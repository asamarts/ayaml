## Why

Typed decoding accepts input that does not match the target, producing values the
caller did not write. `from_value` also rewrites scalars into strings, so
`0x1f` into a `String` target gives `"31"`.

## Acceptance criteria

- [ ] float targets accept only core-schema spellings and finite parsed values; other text is an error
- [ ] a sequence does not decode positionally into a struct
- [ ] a bare variant name does not fill a data-carrying variant
- [ ] `from_value` into a string target rejects non-string values, and its API docs say so
- [ ] `from_str`, `from_str_borrowed`, `from_value`, seeded, and compat paths agree or differ only as documented
