## Why

Typed decoding accepts input that does not match the target, producing values the
caller did not write. `from_value` also rewrites scalars into strings. Its rules have
to match `from_str` on null, booleans, and variant names too.

## Acceptance criteria

- [ ] float targets accept only core-schema spellings and finite parsed values; other text, and a scalar tagged as a string, is an error
- [ ] a sequence does not decode positionally into a struct
- [ ] a bare variant name does not fill a data-carrying variant
- [ ] `from_value` into a string target rejects non-string values, and its API docs say so
- [ ] `from_value` and stream decoding treat null like `from_str` for sequence, mapping, and struct targets, rather than filling in an empty or default value
- [ ] `from_value` selects an enum variant by its exact name, not by a value that merely reads the same
- [ ] `from_str`, `from_str_borrowed`, `from_value`, seeded, and compat paths agree or differ only as documented
- [ ] a tag's `handle()` and `suffix()` don't depend on which reader produced it
