## Why

Some valid and invalid forms around node properties and document starts read as
the wrong data, without any error.

## Acceptance criteria

- [ ] duplicate anchors or tags on one node are errors, not silently dropped
- [ ] a BOM before a document marker after `...` starts a document, not scalar text
- [ ] the non-specific tag `!` is not expanded by a `%TAG !` directive
- [ ] a handle that expands to a core-schema name is validated as that core tag
- [ ] default and compat behavior is stated for each, with suite classifications unchanged or justified
