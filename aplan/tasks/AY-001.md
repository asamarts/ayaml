## Why

ayaml keeps the source span and the immediate Serde expectation, but drops the outer field
and sequence context. A tool that picks its advice from that path can't tell which nested
schema a typo belongs to.

## Acceptance criteria

- [ ] owned, borrowed, seeded, root, and compatibility typed entry points retain nested field and index paths
- [ ] flatten, map, tuple, enum, option, and newtype failures have deterministic paths without duplicated prefixes
- [ ] the source span still identifies the offending token and `ErrorKind::Serde` remains intact
- [ ] a new fixture holding a sequence of nested structs reports the path and the accepted fields
- [ ] root-level errors gain no prefix
- [ ] sequence indices and mapping keys that aren't identifier-like render deterministically
- [ ] default and compat paths agree, unless a documented compat behavior changes the parse before Serde runs
- [ ] path bookkeeping costs nothing on the success path, and default `from_str` stays within its performance gate
