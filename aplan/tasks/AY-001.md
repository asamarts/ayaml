## Why

ayaml keeps the source span and the immediate Serde expectation, but drops the outer field
and sequence context. A tool that picks its advice from that path can't tell which nested
schema a typo belongs to.

## Acceptance criteria

- [x] owned, borrowed, seeded, root, and compatibility typed entry points retain nested field and index paths
- [x] flatten, map, tuple, enum, option, and newtype failures have deterministic paths without duplicated prefixes
- [x] the source span still identifies the offending token and `ErrorKind::Serde` remains intact
- [x] a new fixture holding a sequence of nested structs reports the path and the accepted fields
- [x] root-level errors gain no prefix
- [x] sequence indices and mapping keys that aren't identifier-like render deterministically
- [x] default and compat paths agree, unless a documented compat behavior changes the parse before Serde runs
- [x] path bookkeeping costs nothing on the success path of the readers that decode from events, and default `from_str` stays within its performance gate. `from_value`, and the `Deserializer` methods built on it, keep each string key for the path, so a target that keeps a string key copies it once
