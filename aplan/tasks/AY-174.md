## Why

The adversarial benchmark and performance-tooling audit uncovered broken local reproduction
commands, digest/schema mismatches, and stale or blind CI performance gates:

1. **Broken published command:** `site/src/pages/benchmarks.astro` instructs users to run
   `cargo xtask memory --suite full --out-dir target/xtask`, which fails with exit code 2
   because `fuzz/src/bin/memcount.rs` only accepts `--suite baseline`.
2. **Guaranteed `fixture_manifest_sha256` mismatch:** `site/src/data/benchmarks/fingerprint.json`
   hashes only 26 measured scenarios in alphabetical order, whereas `ayaml_fixtures::manifest()`
   (`cargo xtask fixtures --verify / --json`) hashes all 40 catalog fixtures in declaration
   order, so independent verification always fails.
3. **`schema_version: 1` collision:** `crates/xtask/src/schema.rs` keys records on
   `(scenario, operation)` without `implementation` and requires raw host fields absent from
   sanitized `site/src/data/benchmarks/fingerprint.json`, so `xtask compare`/`gate`/`report`
   collide all 11 implementations or fail to parse the published artifacts.
4. **Up to 4.69x slack in `tools/alloc-baseline.jsonl`:** The committed allocation baseline
   predates recent optimizations (up to +369% slack on `frontmatter-tiny` and +66% to +85%
   slack on `boundary-4kb-*`), `tools/alloc-corpus.tsv` carries 1.25x to 1.31x slack, and
   `tools/typed-alloc-corpus.tsv` covers only a single file. `check_alloc_baseline.py` has no
   ratchet-reminder check when measurements drop sharply below baseline.
5. **Instruction gate blind spots:** `tools/check_instructions.py` compares only `HEAD` vs
   `BASE_REV` (allowing gradual multi-PR creep), uses one coupled override column in
   `tools/instruction-rises.tsv` so an `EstCycles` layout exception silently relaxes `Ir`, and
   `tools/instruction-probe.rs` + `ayaml-bench` + `memcount` have zero coverage for
   `ayaml-edit`, `frontmatter`, `merge_keys`, `Spanned<T>`, `DocumentDeserializer`,
   `from_reader`, `depth-64`, and `libyaml-compat`.

## Scope

1. **Make `cargo xtask memory --suite full` work cleanly:** Implement `--suite full` in
   `fuzz/src/bin/memcount.rs` (running all catalog scenarios + operations cleanly) and verify
   all published commands in `benchmarks.astro` and `docs/benchmarks.md` exit 0.
2. **Align `fixture_manifest_sha256` and `xtask` schemas:**
   - Ensure exported `fingerprint.json` records `ayaml_fixtures::manifest().manifest_sha256`
     (exact 40-fixture catalog digest matching `cargo xtask fixtures --verify / --json`).
   - Extend `crates/xtask/src/schema.rs` to preserve optional `implementation` and `rounds`
     fields, include `implementation` in comparison keys, and accept sanitized published
     `fingerprint.json` files cleanly.
3. **Ratchet allocation baselines and add slack detection:**
   - Re-record `tools/alloc-baseline.jsonl` and tighten `tools/alloc-corpus.tsv` after `AY-173`.
   - Expand `tools/typed-alloc-corpus.tsv` beyond a single file.
   - Add a ratchet warning in `tools/check_alloc_baseline.py` whenever actual peak bytes or
     allocations drop more than 15% below the committed baseline.
4. **Harden Callgrind instruction gate and expand post-0.2.3 perf coverage:**
   - Split `tools/instruction-rises.tsv` into separate `IR_PERCENT` and `CYCLES_PERCENT`
     override columns in `tools/check_instructions.py` and prune stale dropped workload rows.
   - Add workloads in `tools/instruction-probe.rs`, `crates/ayaml-bench`, and `memcount` for
     `ayaml-edit`, `frontmatter`, `merge_keys`, `Spanned<T>`, `DocumentDeserializer`,
     `from_reader`, `depth-64`, and `libyaml-compat` (enabling `libyaml-compat` in
     `check_instructions.py` probe build).
   - Add a pinned release-baseline instruction snapshot so CI detects cumulative creep across
     PRs in addition to per-PR diffs.
