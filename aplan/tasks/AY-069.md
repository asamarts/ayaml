## Why

A core-schema tag names a kind of node, and on a node of another kind both modes treat it two
ways. A collection tag is dropped, so `!!map [a]` reads as a sequence and `!!seq a` as a string.
A scalar tag on a collection is kept, so `!!str {}`, `a: !!int [1]`, `a: !!str\n  b: 1`, and
`!!null []` read as tagged collections, and so does such a tag that a `%TAG` handle expands to.
libyaml drops the tag in each case, so compat reads these differently from it, and nothing
documents either difference.

## Acceptance criteria

- [ ] compat drops a core-schema tag on a node of another kind, as libyaml does, for scalar and collection tags alike, including one that a `%TAG` handle expands to
- [ ] default mode treats every such node one way, either refusing it as an invalid node (YAML 1.2.2 section 3.3.3) or dropping the tag, and `docs/decisions.md` records the choice
- [ ] `parse_value`, the typed readers, and the streamed reader agree on these nodes in each mode
- [ ] compatibility.md and the changelog say what each mode does
