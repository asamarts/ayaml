## Why

Issue #178: documents of many short scalars hold one token and one typed node per scalar during
the parse. Scalar tokens carried raw text beside the decoded value, every token paid for the
largest tag and directive variants, and every typed node held a tag inline even when untagged.

## Acceptance criteria

- [x] a scalar token stores its raw text as its span and boxes only values that need decoding
- [x] tag and directive token payloads are boxed, and a token is at most 32 bytes on 64-bit targets
- [x] typed nodes box their tag, and a node is at most 96 bytes on 64-bit targets
- [x] the 11 MB typed peak falls to about 333 MB and total to about 459 MB; the 1 MB document to about 33.3 MB peak and 46.4 MB total; the 20 KB configuration to about 281 KB peak and 509 KB total
- [x] short-scalar shapes fall by roughly a third, with the remaining gap tracked by #178
- [x] allocation budgets are tightened and both test modes plus conformance pass
