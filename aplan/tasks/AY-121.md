## Why

`main` has carried breaking changes since byte-offset spans landed, so no 0.1.x release can come
from it, and every fix merged since 0.1.3 waits for the next minor release. D90 cuts that release
as soon as the breaks that are already decided are in: byte-offset spans, the lazy compatibility
event readers, and `Mapping`'s own iterator types. The additive interface work follows in 0.2.x.

Tag `v0.2.0` (`423361d`) was held before publishing after post-tag audits and differential fuzzing
surfaced the fixes closed in `AY-126`, `AY-127`, and `AY-128`. Per `RELEASING.md`, the `v0.2.0` tag
stays in place as an unpublished version, and `0.2.1` becomes the first published `0.2.x` release
carrying every `0.2.0` change plus `AY-126`, `AY-127`, and `AY-128`.

## Acceptance criteria

- [x] the changelog's section for 0.2.1 (and 0.2.0) states that 0.2.0 was never published and lists each breaking change first, with what a caller has to change: spans and positions, an error's location, `compat::parse_events_with_limits` and its eager form, and `Mapping`'s iterator types
- [x] every place that repeats the version states 0.2.1, which the policy test checks
- [x] `LineIndex` gives every shared position vector, with the contract's names and zero-based positions (AY-051, D96)
- [x] `SECURITY.md` names the versions that get fixes once 0.2.1 is out
- [x] the timing and peak-memory comparison passes on a quiet host at the release commit (D68), and the comparison gates pass, with every difference in what is read reviewed
- [x] both consumers build against the release commit with their migration, and every test of theirs that then fails, and every difference their own comparisons then report, is traced to a change that the changelog states; one that is a defect here is fixed first
- [x] the property suite passes at 10,000 cases a property, and the fuzz workflow passes on the tag's commit
- [x] ayaml 0.2.1 is published from the attested tag by the release workflow
- [x] the tag, its commit, the crate's digest, and the release's address are recorded here
