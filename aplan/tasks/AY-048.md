## Why

Each combination of options has its own function name, which gives 27 root emit functions,
while some entry points have no limits form at all. Every new option multiplies names.

## Acceptance criteria

- [ ] `ParseOptions` and `EmitOptions` are `non_exhaustive`, with `with_*` builders and `const` presets where possible
- [ ] each operation has one `_with` function, and every entry point can take limits, compat's included, so a caller can set its own budgets for compat reads
- [ ] the old combination functions are deprecated through 0.x, with a pointer to the replacement, and removal at 1.0 is stated
- [ ] the `Mapping` iterator newtypes planned by AY-044 land in this release
- [ ] `cargo-semver-checks` output matches the changelog
