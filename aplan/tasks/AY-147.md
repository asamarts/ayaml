## Why

Container specs and CI pipeline configurations rely heavily on `<<:` merge keys
combined with anchors. Today `Value::apply_merge_keys` only operates after
composing a `Value` (losing source spans and borrowed strings, and treating
quoted `"<<"` identically to plain `<<`). Providing an opt-in merge mode at the
event/typed layer preserves spans, scalar-style distinction, and resource bounds
while leaving default YAML 1.2.2 parsing untouched.

## Acceptance criteria

- [x] an opt-in merge-key expansion option is available for typed and event-driven reading while default parsing continues to keep `<<` literal
- [x] plain `<<` keys expand while quoted `"<<"` keys remain literal mapping keys
- [x] explicit own keys override merged keys, sequence operands honor first-wins precedence, chained merges flatten, source spans remain accurate, and depth/alias/expansion budgets are strictly enforced
- [x] unit, property, and `in_child!` adversarial tests verify merge semantics and hostile merge-bomb rejection
