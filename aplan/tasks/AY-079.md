## Why

Three consecutive nightly workflows failed: first the borrowed-reader target, then the emitter
target twice. Hosted policy sealed the logs and reproductions, so public CI cannot determine whether
they are one defect, several defects, or a stale corpus problem. Scanner, parser, and emitter module
splits must not move the relevant code before the sealed findings are reproduced against their
original commits.

## Acceptance criteria

- [x] every sealed artifact from the three failed runs is preserved before expiry, decrypted privately, and classified; no input or revealing log is published before its fix
- [x] each finding is reproduced under the repository's sanitizer timeout and RSS limit against the exact commit that produced it, or the artifact records enough evidence to show why it is not reproducible
- [x] every reproducible correctness, resource, or round-trip defect is fixed at its cause without weakening a limit, assertion, or fuzz oracle
- [x] the emit target counts non-directive events, so a valid tag that needs a generated `%TAG` directive round-trips without a changed event count, while a dropped or duplicated non-directive event still fails
- [x] a minimized regression enters the appropriate test or fuzz corpus only with the fix, and any corpus cache that keeps rediscovering a removed artifact is deliberately replaced
- [ ] parse, borrowed, and emitter fuzz targets pass bounded local smoke runs and a hosted nightly run on the fixed commit
- [ ] issue 69 is updated without sensitive details and closed only after every sealed artifact has been examined and the scheduled watcher observes a healthy run
- [ ] AY-073, AY-074, and AY-075 begin only after the pre-split reproductions are preserved and understood

## Status

An audit on 2026-11-10 preserved and decrypted the three artifacts. The borrowed target's saved
input no longer reproduces at the audited commit; the streamed reader now refuses that input at the
same point as the composed reader. The emitter target still reproduces two independent failures: an
invalid verbatim tag that the reader accepts and the writers refuse, and a valid tag that needs a
`%TAG` directive the writers add (D82), which changes the event count the target compares. The first
is AY-025's remaining verbatim-tag criterion; the second needs the target's count corrected for
generated directives.
