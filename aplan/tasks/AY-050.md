## Why

Changing a YAML file safely is harder than producing a span. Each edit should be proven
before it is returned, as adotenv's edits are. This belongs in its own crate, because its
rules will change faster than the parser's.

## Acceptance criteria

- [ ] the crate uses only ayaml's public API
- [ ] it offers scalar replacement and whole-entry removal, returning verified edits with private fields, the output text, and sorted, non-overlapping `TextEdit`s, with an insertion first when two edits start at the same offset
- [ ] each result is reparsed and its events and values compared before it is returned
- [ ] anchors, aliases, tags, block scalars, multiple documents, and ambiguous comment placement are refused until proven safe
- [ ] a byte-order mark, CRLF, comments, and neighboring bytes are preserved
- [ ] a property test and a fuzz target check that output parses and unrelated values do not change
- [ ] the first publish and the Trusted Publisher setup are documented
