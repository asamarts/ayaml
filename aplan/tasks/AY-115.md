## Why

The token arena is sized from the density of the whole prefix scanned so far. After a head with
few tokens, such as a megabyte of comment lines or one block scalar, the average stays low while
a dense tail fills the arena, so each new estimate is barely more than the arena holds and it
grows by a sixteenth at a time. A review measured `read_lines` reallocations, where a document of
even density takes three:

| Head | Tail of `- a` lines | Reallocations |
| --- | --- | --- |
| 1 MiB of comment lines | 250,000 | 11 |
| 1 MiB block scalar | 100,000 | 16 |
| 8 MiB of comment lines | 250,000 | 34 |
| 28 MiB of comment lines, default limits | 500,000 | 48 |

The copies come to 225 MB for the 8 MiB head and 500 MB for the 28 MiB head, against 30 MB for an
even document. It is within the bound `docs/limits.md` gives, a sixteenth at least, and 0.1.3 was
worse, so it is not a regression. The test of a sparse prefix uses a 33 KB head, which is too
short to show it.

Separately, a reservation is made with `reserve_exact`, which panics when the capacity overflows.
On a 32-bit target that takes an input limit raised past about 128 MiB and the count limits
lifted, so the defaults can't reach it, but a raised limit should end in an error and not a panic.

Two parts of the estimate change nothing that a test or a budget sees: the reservation made at
the threshold, since a full arena gets the same estimate a token later, and the state that keeps a
mid-sized input from estimating at all.

## Acceptance criteria

- [ ] an estimate made when the arena is full weighs the density since the last estimate, within the caps the arena already has, so a megabyte head before a dense tail takes about as many reservations as an even document
- [ ] a test with a head of at least a megabyte bounds the reservations, and the tests of a dense prefix before a sparse rest still pass
- [ ] a reservation that would overflow is an error with the token limit's kind, on any target
- [ ] the reservation at the threshold and the state that never estimates are each removed, or pinned by a test that fails without them
- [ ] `docs/limits.md` states the arena's growth as it then is
