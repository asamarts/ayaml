## Why

Libyaml accepts an alias directly followed by `:` as an implicit mapping key, while ayaml
0.1.1 requires a separator before the colon. The anchor-name grammar makes this ambiguous,
so the quirk belongs only in the explicit compatibility path.

Suite cases 2SXE and W5VH define anchors whose names really end in a colon, and
compat deliberately reads them that way. So compat uses an exact-anchor rule: an
alias name ending in `:` keeps the colon only if an anchor with exactly that name
is defined in the current document, and otherwise stops before it. A plain colon
stop would silently change the value in 2SXE and reject W5VH.

## Acceptance criteria

- [ ] an alias name ending in `:` keeps the colon only when that exact anchor is defined in the current document, with the set reset at document boundaries
- [ ] the compat suite keeps 13 listed deviations with 0 unexpected, including 2SXE and W5VH
- [ ] an alias matching no anchor reports an unknown anchor
- [ ] the anchor-name set exists only in compat mode, and the quiet-host gates measure compat `from_str` against the baseline, since the existing rows measure only the root path
- [ ] compatibility generic and typed entry points accept an alias directly followed by `:` as an implicit block mapping key
- [ ] the separated form keeps working in both modes, and enabling the `libyaml-compat` feature changes no root entry point
- [ ] alias resolution reaches duplicate-key or duplicate-field handling with the expected location
- [ ] default YAML 1.2.2 entry points keep their explicitly tested behavior
- [ ] unknown aliases, alias cycles, punctuation, flow forms, and every alias/resource limit remain fail-closed
- [ ] compatibility documentation and the deviation list state the disposition
