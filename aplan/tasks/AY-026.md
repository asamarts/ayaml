## Why

Limits disagree across paths: the lazy cursor counts events more than once, event
paths count depth lower than value paths, one budget differs on the borrowed path,
and two limits are documented differently from how they measure.

## Acceptance criteria

- [ ] event counts match between lazy and eager parsing
- [ ] `max_events` counts what its name and docs say: events rather than scanner tokens, or the docs define the unit
- [ ] a blank or comment line doesn't count against `max_events`. Outside a flow collection each one counts now, in both modes, so about a million of them between two entries refuse a document far under `max_input_bytes`
- [ ] depth is counted the same on event, value, and typed paths
- [ ] alias expansion accounting is the same on value paths and typed-builder paths
- [ ] `max_anchors` is stated per stream, or enforced per document, consistently
- [ ] `max_scalar_bytes` also bounds decoded size, and the docs say what it measures
- [ ] a consistency test runs the same input at the same limits through every entry point
