## Why

Limits disagree across paths: the lazy cursor counts events more than once, event
paths count depth lower than value paths, one budget differs on the borrowed path,
and two limits are documented differently from how they measure.

D78 keeps `max_events` as one limit over events and the tokens a read keeps, with no line break
counted, and D79 counts `max_anchors` per stream, as every reader enforced it. `docs/limits.md`
says what each limit counts. The one difference left between readers is by design: the readers that
build values copy an alias's target, so its collections count toward their depth and its nodes
against their alias budget, and an event reader sees the alias alone.

## Acceptance criteria

- [x] event counts match between lazy and eager parsing
- [x] `max_events` counts what its name and docs say: events rather than scanner tokens, or the docs define the unit
- [x] a blank or comment line doesn't count against `max_events`. Outside a flow collection each one counts now, in both modes, so about a million of them between two entries refuse a document far under `max_input_bytes`
- [x] depth is counted the same on event, value, and typed paths
- [x] alias expansion accounting is the same on value paths and typed-builder paths
- [x] `max_anchors` is stated per stream, or enforced per document, consistently
- [x] `max_scalar_bytes` also bounds decoded size, and the docs say what it measures
- [x] a consistency test runs the same input at the same limits through every entry point
