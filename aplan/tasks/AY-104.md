## Why

Issue #178: one document shape of many short scalars still peaked above the 1.2x target. Typed
decoding built a complete `Node` tree, 80 bytes a node, before it built the target value, and
that tree was live together with the token arena, which holds every token for the whole input.

## What was done

A reader of one document into a type reads an input of more than 4 KiB from the parser's events,
which it takes as the target asks for values (D95). The parser's grammar, which already ran on an
explicit stack, stops between two steps and goes on when the next event is asked for. A scalar is
read and dropped, a collection is read entry by entry, and a tree is built only of what is read
whole or again. Every error is the one that a read which builds the tree gives, so a refused
input is read a second time.

Measured as the issue measures it, an untyped decode into a JSON tree through the compatibility
reader, the nine shapes peak at 0.52 to 0.96 times the issue's reference. The megabyte block
sequence of short words fell from 23.1 MB, 1.28 times, to 17.4 MB, 0.96 times. A typed read of
many short entries executes about 4% more instructions than one that builds the tree.

The figures this task first held, such as 98 MB for a flow sequence of `1`, measured a decode
into ayaml's own `Value`, another tree than the issue's, against the issue's reference.

## Acceptance criteria

- [x] untyped serde seeds can consume events or values without retaining a complete typed node tree
- [x] duplicate keys, tags, aliases, limits, and typed error paths keep their current behavior: the two readers give the same value or error on the test documents, on generated ones, and in the `borrowed` fuzz target, and the whole suite passes with every typed read made from events
- [x] the megabyte block sequence of short words peaks within 1.2 times the issue's reference, and no other shape of #178 leaves it
- [x] the budgets in `tools/json-alloc-corpus.tsv` and the typed budgets are lowered to the new measurements, and both test modes plus conformance pass
- [x] the issue's shapes are recorded with the measurements, in the allocation gate (AY-113)
- [x] a visitor that takes an entry's error and reads on, reads nothing, or leaves values behind gets what a tree gives it, and a fault in the document stands whatever the visitor does
