## Why

Issue #178: one document shape of many short scalars still peaks above the 1.2x target. Typed
decoding builds a complete `Node` tree, 80 bytes a node, before it builds the target value, and
that tree is live together with the token arena, which holds every token for the whole input.

## Current state

Measured as the issue measures it, an untyped decode into a JSON tree through the compatibility
reader, eight of the nine shapes are within 1.2 times the issue's reference, at 0.61 to 1.06
times. `tools/json-alloc-corpus.tsv` budgets all nine (AY-113). The ninth, a megabyte block
sequence of short words, peaks at 23.1 MB, 1.28 times, where 1.2 times allows 21.7 MB. At that
peak the token arena (8.4 MB), the typed node vector (10.5 MB), the line records (3.2 MB), and
the line index (1.0 MB) are live, and the JSON tree, 4.8 MB, is not yet built. Building the
value as the events arrive takes the node vector out of that peak.

The figures this task first held, such as 98 MB for a flow sequence of `1`, measured a decode
into ayaml's own `Value`, a larger tree than the issue's, against the issue's reference.

## Acceptance criteria

- [ ] untyped serde seeds can consume events or values without retaining a complete typed node tree
- [ ] duplicate keys, tags, aliases, limits, and typed error paths keep their current behavior
- [ ] the megabyte block sequence of short words peaks within 1.2 times the issue's reference, and no other shape of #178 leaves it
- [ ] the budgets in `tools/json-alloc-corpus.tsv` and the typed budgets are lowered to the new measurements, and both test modes plus conformance pass
- [x] the issue's shapes are recorded with the measurements, in the allocation gate (AY-113)
