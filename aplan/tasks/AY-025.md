## Why

Invalid forms parse without error. These rejections are bug fixes, stated in the
changelog. Each applies in default and compat mode unless a criterion says otherwise.

## Acceptance criteria

- [x] block collections on a `---` line that the grammar forbids are rejected on every entry point, including the streamed one, and the narrow skip in `fuzz/fuzz_targets/borrowed.rs` goes away, which `a_block_collection_cannot_start_on_a_document_start_line` checks
- [x] repeated, contradictory, or out-of-range block scalar indicators, and whitespace before an indicator, are rejected, which `a_block_scalar_header_has_one_indicator_of_each_kind` checks
- [x] empty verbatim tags, empty `!!` tags, a named handle with no suffix, and a verbatim `!` are rejected, which `tag_names_are_checked` checks
- [x] a `%` in a verbatim tag without two hex digits after it is rejected, once AY-018 writes every tag that a verbatim tag can't hold in another form, since `!e!50%25` is written `!<tag:x:50%>` today
- [x] a document marker line inside a multi-line plain scalar in a flow collection is rejected, which `a_document_marker_line_ends_a_plain_scalar_in_a_flow_collection` checks
- [x] a tab before a block sequence entry or an explicit mapping key, at the start of a line or after another such indicator or a `:` indicator, is rejected, whichever separator follows the indicator, which `a_tab_cannot_indent_a_block_collection` checks
- [x] a flow `?` directly followed by a flow indicator is rejected; compat keeps its existing reading of `?` before other text, which `a_flow_collection_s_question_mark_is_separated_from_a_flow_indicator` checks
- [x] duplicate `%TAG` handles in one document are rejected, which `a_tag_handle_has_one_prefix_in_a_document` checks
- [x] multi-line quoted scalars respect the indent check, after a compact key or entry on the line too: by default, `- k: 'a\n b'`, `- - 'a\n b'`, and `- k: [ 'a\n b' ]` need three spaces, while compat reads them, as libyaml does and as real files rely on, which `a_quoted_scalar_after_a_compact_key_is_held_to_its_collection` checks
- [x] a plain scalar's continuation lines in a flow collection under a block collection respect the indent check, by default, which `a_flow_collection_s_lines_are_indented_past_its_block_collection` checks
- [x] flow and quoted lines under nested block collections are measured against the innermost collection, by default, which `a_flow_collection_s_lines_are_indented_past_its_block_collection` checks
- [x] a quoted scalar's line under a block collection isn't exempt from the indent check because it starts with the other kind of quote or an escaped quote: `k: "a\n'b"` and `k: 'a\n''b'`, which `a_quoted_line_is_held_to_the_indent_whatever_quote_starts_it` checks
- [x] a tab alone doesn't indent a block node under a key or indicator, nor a plain scalar's line in a flow collection under a block collection, in compat too: `k:\n\tv`, `k:\n\t{a: b}`, `k:\n\t'a: b'`, `-\n\t[a]`, `k:\n\t|\n  x`, and `k: [a\n\tb]`, which `a_tab_alone_indents_no_nested_node` checks
- [x] a byte order mark in a comment after a block scalar header is rejected by default, as in any other comment, while compat reads it, as libyaml does and as compat does in any other comment, which `a_block_scalar_header_comment_holds_no_byte_order_mark` checks
- [x] in compat too, an implicit flow key's `:` on a line not indented past the block collection around it is rejected, while compat reads an explicit key's there, as libyaml does, which `a_flow_key_s_colon_needs_an_indented_line` checks
- [x] a tab on a blank line inside a multi-line scalar under a block collection, before the scalar's indentation, is rejected by default (`l-empty`, production 70), as in `k:\n  a\n\t\n  b`, `k: [a\n\t\n b]`, and `k: "a\n\t\n b"`, and in compat in a plain scalar, as libyaml rejects it there, which `an_empty_line_inside_a_scalar_holds_no_tab_before_its_indentation` checks
- [x] a verbatim tag that isn't a valid global or local tag name is rejected, as in the specification's example 6.25, once AY-018 writes every tag that a verbatim tag can't hold in another form, since a `%TAG` prefix without a scheme, as in `%TAG !e! foo` and `!e!bar`, is written `!<foobar>` today
- [x] enum variant selection takes a tag's whole name, so a foreign handle's suffix alone selects no variant: under `%TAG !e! tag:x:`, `!e!B` and `!<tag:x:B>` both select the variant `<tag:x:B>`, and `!!C` selects `<tag:yaml.org,2002:C>`, on every typed path, which `a_tag_names_an_enum_s_variant_by_its_whole_name` checks
- [x] enum variant selection refuses the mapping forms it should not accept: only a mapping of one entry whose key is a string names a variant, as in `B: 5`, as AY-021's criteria expect, on every typed path and in both modes (D80), which `an_enum_reads_one_mapping_form` checks
- [x] each change is stated in the changelog, with suite classifications unchanged or justified
