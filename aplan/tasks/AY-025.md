## Why

Invalid forms parse without error. These rejections are bug fixes, stated in the
changelog. Each applies in default and compat mode unless a criterion says otherwise.

## Acceptance criteria

- [ ] block collections on a `---` line that the grammar forbids are rejected on every entry point, including the streamed one, and the narrow skip in `fuzz/fuzz_targets/borrowed.rs` goes away
- [x] repeated, contradictory, or out-of-range block scalar indicators, and whitespace before an indicator, are rejected, which `a_block_scalar_header_has_one_indicator_of_each_kind` checks
- [x] empty verbatim tags, empty `!!` tags, a named handle with no suffix, and a verbatim `!` are rejected, which `tag_names_are_checked` checks
- [ ] a `%` in a verbatim tag without two hex digits after it is rejected, once AY-018 writes every tag that a verbatim tag can't hold in another form, since `!e!50%25` is written `!<tag:x:50%>` today
- [ ] a document marker line inside a multi-line plain scalar in a flow collection is rejected
- [x] a tab before a block sequence entry or an explicit mapping key, at the start of a line or after another such indicator or a `:` indicator, is rejected, whichever separator follows the indicator, which `a_tab_cannot_indent_a_block_collection` checks
- [ ] a flow `?` directly followed by a flow indicator is rejected; compat keeps its existing reading of `?` before other text
- [x] duplicate `%TAG` handles in one document are rejected, which `a_tag_handle_has_one_prefix_in_a_document` checks
- [ ] multi-line quoted scalars respect the indent check, after a compact key or entry on the line too: `- k: 'a\n b'`, `- - 'a\n b'`, and `- k: [ 'a\n b' ]` need three spaces
- [ ] a plain scalar's continuation lines in a flow collection under a block collection respect the indent check, by default
- [ ] flow and quoted lines under nested block collections are measured against the innermost collection, by default
- [ ] a quoted scalar's line under a block collection isn't exempt from the indent check because it starts with the other kind of quote or an escaped quote: `k: "a\n'b"` and `k: 'a\n''b'`
- [ ] a tab alone doesn't indent a block node under a key or indicator, nor a plain scalar's line in a flow collection under a block collection, in compat too: `k:\n\tv`, `k:\n\t{a: b}`, `k:\n\t'a: b'`, `-\n\t[a]`, `k:\n\t|\n  x`, and `k: [a\n\tb]`
- [x] a byte order mark in a comment after a block scalar header is rejected by default, as in any other comment, while compat reads it, as libyaml does and as compat does in any other comment, which `a_block_scalar_header_comment_holds_no_byte_order_mark` checks
- [ ] in compat too, a flow key's `:` on a line not indented past the block collection around it is rejected
- [ ] a verbatim tag that isn't a valid global or local tag name is rejected, as in the specification's example 6.25, once AY-018 writes every tag that a verbatim tag can't hold in another form, since a `%TAG` prefix without a scheme, as in `%TAG !e! foo` and `!e!bar`, is written `!<foobar>` today
- [ ] enum variant selection ignores foreign-handle tags and mapping forms it should not accept
- [ ] each change is stated in the changelog, with suite classifications unchanged or justified
