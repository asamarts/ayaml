## Why

A pre-1.0 adversarial review of the parser, spanned builder, merge-key processor, and emitter
identified three resource-bound gaps that must be closed before tagging `1.0.0` and running
the extended soak campaign:

1. `crates/ayaml/src/spanned.rs` (`missing_value_place`) scans to the next line break on every
   empty-value entry even inside flow mappings, recomputes the mapping's column from the start
   of the line on each empty entry, and re-scans trailing blank/comment lines per closing block
   frame. On dense inputs within default `Limits`, this causes quadratic CPU work.
2. `crates/ayaml/src/merge/events.rs` (`apply_event_merge`) copies the caller's `AliasBudget`
   into a local `key_budget` before materializing mapping keys via `node_key_value` and then
   discards the local copy without charging the spent budget back to the stream-level budget,
   allowing repeated key-materialization work to bypass alias expansion limits under
   `ParseOptions::with_merge_keys(true)`.
3. `crates/ayaml/src/emitter.rs` (`ValueWriter::emit_flow`) does not check `self.error.is_some()`
   inside its sequence and mapping loops, continuing to format and allocate remaining entries
   after hitting `max_output_bytes` or an `io::Write` failure.

## Scope

1. **Linear-time spanned-tree missing-value and trailing-line scanning (`crates/ayaml/src/spanned.rs`):**
   - In `missing_value_place`, handle flow mappings by inspecting only the immediate bytes after
     the key indicator (skipping inline spaces/comments without scanning to EOF or line end).
   - Cache the mapping's starting column on the active frame instead of rescanning from line
     start on every empty-value entry.
   - Bound or memoize trailing blank/comment line scans in `block_scalar_ignores_after`,
     `value_indicator_follows`, and `entry_end` so nested block closings followed by long runs
     of blank or comment lines remain linear in input length.
2. **Stream-cumulative alias budget accounting in event-layer merge keys (`crates/ayaml/src/merge/events.rs`):**
   - Charge `node_key_value` materialization against the persistent stream-cumulative budget so
     sibling mappings with merge keys cannot reset key-inspection expansion costs to zero.
   - Preserve exact limit diagnostics (`AliasExpansionLimit` / `AliasDereferenceLimit`) when
     exceeded.
3. **Early exit on error in `ValueWriter::emit_flow` (`crates/ayaml/src/emitter.rs`):**
   - Check `if self.error.is_some() { break; }` at the top of both the sequence and mapping
     loops in `emit_flow`, matching block-mode loops.
4. **Process-isolated adversarial regression tests (`crates/ayaml/tests/adversarial/dos.rs`, `crates/ayaml/tests/adversarial/merge.rs`):**
   - Add `in_child!`-bounded regression tests covering dense empty-value flow mappings in
     `SpannedTree::parse`, deeply nested block closings with large trailing blank runs,
     repeated alias-key merge mappings in `parse_events_with` and `SpannedTree::parse_with`,
     and large flow emission under tight `max_output_bytes` and failing writers.

## Acceptance criteria

- [x] `SpannedTree::parse` completes dense flow empty-value and trailing-blank inputs in linear time within child-process memory and deadline bounds
- [x] `parse_events_with` and `SpannedTree::parse_with` with `merge_keys(true)` enforce cumulative alias-expansion budgets across sibling mappings
- [x] `ValueWriter::emit_flow` stops immediately after the first limit or I/O error without formatting remaining elements
- [x] new `in_child!` adversarial tests, full `cargo test --workspace --all-features --locked`, forced `--cfg ayaml_typed_from_events`, and Callgrind/allocation gates pass
