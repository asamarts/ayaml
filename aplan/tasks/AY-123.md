## Why

A typed read keeps each key it has seen in a mapping, to refuse a second one. A key that is a
scalar is kept as its text. A key that is a collection is kept as a copy of its node, so a key
nested in keys is copied once at every level: reading a mapping of 1,000 entries that is a key
100 levels deep into a typed value executes 4.3 times the instructions of the same key one
level deep, by the instruction gate's count. `parse_value` copies no key and still executes 1.8
times, for a cost at each level that isn't traced yet. Depth is bounded, so both factors are
too, and a copy is freed when its mapping ends, so memory isn't multiplied. The timing test of
nested keys passes at 3.4 to 3.7 times against its bound of 4, which is little room on a busy
host. The gate's `nested-keys` workload holds the counts where they are.

## Acceptance criteria

- [x] a typed read hashes and compares a key that is a collection in place, or moves it, and doesn't copy it, from a tree and from events
- [x] what `parse_value` does once for every entry of a key at every level is found, and done once
- [x] the `nested-keys` workload of the instruction gate falls for the typed read and for `parse_value`, to under 1.5 times the count at depth 1
- [x] the readers still refuse the same duplicate keys, a reordered mapping key among them, with the same errors
