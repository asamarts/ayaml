## Why

The pinned semver checker reported no break between 0.1.3 and the tree that became 0.2.0,
which has four: `Span`'s accessors return another type, `Span::new` takes another, a
compatibility event reader returns another, and `Mapping`'s three `IntoIterator`
implementations name other iterator types. It has no rule for a changed parameter, return, or
associated type. The 0.2.x releases are meant to add to the interface and break nothing, and
the plan held them to that with the checker alone. A source test keeps one known leak out, the
type of the map behind `Mapping`, and nothing looks at the API as a whole.

## Acceptance criteria

- [ ] CI builds a listing of the public API, for each feature set that changes it, and compares it with the listing of the last released tag
- [ ] a pull request that removes an item or changes a signature, a trait implementation, or an associated type fails unless the changelog's Changed section names the item
- [ ] the check reports each of the four breaks of 0.2.0 when it compares that release with 0.1.3
- [ ] the tool is pinned by version and checksum, as the other gate tools are, and `tools/ci-local.sh` runs the same check
