## Why

The scanner read a line again for each tab, each quoted scalar on a line of a flow collection,
each line of a plain scalar after a long prefix or a run of byte order marks, and each byte order
mark in a document prefix.
Outside ASCII, the line index counted a line's characters again for each token, so a long line
with one non-ASCII character was enough, as in minified JSON. Input of those shapes took time
quadratic in its length. An 800 KB input could take over a minute, and the default limit allows
32 MiB, so `Limits` didn't bound the time an untrusted document could cost.

## Acceptance criteria

- [x] a run of tabs, in a block or flow context, is checked once, and a line's runs together read it once
- [x] a token's column on a line with non-ASCII text counts on from the last column
- [x] a plain scalar reads the text before it on its line once, however many lines it has
- [x] a quoted scalar in a flow collection finds its line's start and indent without reading the line again
- [x] byte order marks in a document prefix are scanned once, on one line or on many
- [x] a plain scalar with many lines after a run of byte order marks reads the run once
- [x] a test fails, within its bounds, when any of these shapes goes quadratic again
- [x] the changelog states the change
