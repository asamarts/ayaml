## Why

The workspace currently forbids unsafe code and opts into only `dbg_macro`, `todo`, and
`unimplemented`. Stable Clippy finds roughly 300 pedantic diagnostics before rustc and selected
nursery/restriction checks, while the production library has 17 `expect` sites and two explicit
panics. The policy should catch API documentation, lossy conversions, stale suppressions, and
panic-prone shortcuts without enabling unstable or internally contradictory lint groups.

## Acceptance criteria

- [x] main-workspace rustc policy keeps `unsafe_code = "forbid"` and warns on `future_incompatible`, `rust_2018_idioms`, `missing_docs`, `missing_debug_implementations`, `unreachable_pub`, `unused_lifetimes`, `unused_qualifications`, `trivial_casts`, `trivial_numeric_casts`, and `let_underscore_drop`
- [x] main-workspace Clippy policy enables `all`, `cargo`, and `pedantic` at group priority -1; `multiple_crate_versions`, `module_name_repetitions`, and `similar_names` are the only policy-wide allows
- [x] the complete `nursery` and `restriction` groups stay disabled; main-workspace policy selects only `allow_attributes_without_reason`, `dbg_macro`, `literal_string_with_formatting_args`, `mem_forget`, `needless_pass_by_ref_mut`, `or_fun_call`, `redundant_clone`, `todo`, and `unimplemented` from them
- [x] `dbg_macro`, `todo`, and `unimplemented` are denied, and one-off suppressions use the narrowest `#[expect(..., reason = "...")]` or justified `#[allow(..., reason = "...")]`
- [x] `clippy.toml` raises the function-size threshold to 200 lines and does not duplicate the `rust-version = "1.88"` MSRV already declared in Cargo metadata
- [x] a production-library Clippy profile additionally denies `unwrap_used`, `expect_used`, and `panic`; the existing 19 sites are removed or individually justified as checked invariants or required panicking trait behavior
- [x] `indexing_slicing`, `string_slice`, `as_conversions`, `arithmetic_side_effects`, and the whole restriction group remain off because the scanner has many proven-boundary operations where blanket rewrites or suppressions would obscure rather than improve safety
- [x] the separate fuzz workspace declares the 1.88 MSRV, mirrors the applicable rustc and Clippy policy, and runs Clippy and rustfmt in both toolchain jobs; each fuzz target forbids unsafe code, with the documented counting allocator as the only crate-local exception
- [x] rustdoc enables `rustdoc::all`, retains `-D warnings`, and every public `Result` API has an accurate `# Errors` section; `missing_docs` stays clean
- [x] stable rustfmt options explicitly select edition/style edition 2024, Unix newlines, field-init shorthand, and try shorthand, and both Rust 1.88 and stable accept the configuration
- [x] Rust 1.88 and stable Clippy pass for the main workspace and separate fuzz workspace, all targets, and all features with `-D warnings`; the production-library panic profile, both rustfmt invocations, stable feature-combination checks, and rustdoc pass on both toolchains
- [x] lint-driven code changes preserve parser/emitter behavior and do not add avoidable allocations, copies, branches, or computation; bounded tests, strict suites, allocation checks, and instruction checks pass
- [x] CONTRIBUTING and a separate Rust-lint decision record explain group selection, local exceptions, the moving-stable update policy, the production-only panic profile, fuzz-workspace policy, and why new lint findings are fixed or explicitly decided rather than baselined
