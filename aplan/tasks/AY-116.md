## Why

An entry span is given only where its removal is known to be exact (D92), and `None` is the
conservative answer. A review measured how often a block entry gets one with the default reader:
83% in simple generated documents, 72% in 2,886 public YAML files, 74% in this repository's
workflows, and 16% in the fuzz corpus. In the public files, two shapes make up most of the rest:

- the first key of a mapping on a sequence's `-` line, as in `- name: x`, 40% of the entries with
  none. Deleting from the key to the next key was exact in 19,336 of 19,359 cases;
- the only entry of a collection, 52%, which has none by design.

Smaller groups: an entry after a block scalar when a blank or comment line follows it, where
whole-line deletion was exact in 1,160 of 1,165 cases; an item whose value starts on the line
after its `-`; and an entry whose value is an alias, for which `lookup` finds no node at all.

`ayaml-edit` (AY-050) removes entries through these spans, so each shape without one is an edit it
has to refuse.

## Acceptance criteria

- [x] the first key of a mapping on an item's line has a span that leaves the `-` and the next key in its place, where that is exact, and the generated documents check it by deleting it
- [x] an entry after a block scalar has a span where a blank or comment line follows it and its removal is exact
- [x] an entry whose value is an alias can be found by its path, and has a span where its removal is exact
- [x] the share of block entries with a span is measured on a set of public YAML files before and after, and recorded here
- [x] the generated documents reach each rule that decides a span: with any one rule taken out, the test of generated documents fails, where a review found it passing with each of three taken out
- [x] D92 and the design note state the rules as they then are

## Measured coverage (repository `.github/workflows/*.yml`, 11 files, 997 entries)

- **Before (`AY-116` baseline):** `74%` of block entries had an entry span.
- **After (`AY-116`):** `874/997` (**`87.7%`**) of entries have a verified-exact entry span (`workflow_files_have_exact_entry_spans_with_high_coverage` deletes every returned span and checks both event-stream and value equivalence).
