## Why

Linters, schema validators, and configuration diagnostics frequently need both a
typed Rust field value and the exact YAML source `Span` where that value appeared,
without walking a separate `SpannedTree` alongside Serde deserialization.

## Acceptance criteria

- [x] a public `Spanned<T>` wrapper deserializes any `T: Deserialize` together with its exact byte `Span` through `ayaml`'s source-backed typed readers (both small-tree and event-stream paths)
- [x] behavior under aliases, tags, nested structs/sequences/maps, borrowed strings, and non-`ayaml` deserializers is clearly specified and tested
- [x] property tests verify `Spanned<T>` spans are valid UTF-8 boundaries and match `SpannedTree` spans on the same inputs
