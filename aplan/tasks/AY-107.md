## Why

Two changes since 0.1.3 altered what a typed reader says, on code that is in no release. A typed
node kept its text for plain scalars only, so a quoted or block scalar that a core tag makes a
number, a boolean, or a null no longer read into a string target, and a quoted null under a tag
read as an empty collection, against D87. And an input over 8 KiB is built as it is parsed, so a
document with two problems reported a different one once it grew past that size.

## Acceptance criteria

- [x] a scalar that a core tag retypes reads into a string target by its text in every style, as in 0.1.3
- [x] an explicit null under a tag is refused for a sequence, mapping, or struct in every style, and a scalar with no text is a missing value
- [x] a value that only an escape sequence spells keeps no text: it reads as its tag's type, a string target refuses it, and the changelog says so
- [x] a typed reader of one document reports the first problem in the document at every input size, as `parse_value` does (D91)
- [x] the same input after 4 KiB and 8 KiB of comments gives each reader the same answer, with only the place moved
