## Why

Issue #127: typed reads still held one document's events and grew the token arena through several
copies, so total allocation stayed above the libyaml reference even after the chunked and
mid-size work.

## Acceptance criteria

- [x] typed inputs over 8 KiB stream events into the builder without retaining a document event vector
- [x] the token arena estimates its final size from the scanned prefix, capped by input length and line count
- [x] comment-only prefixes and large scalars keep the growth strategy
- [x] the 11 MB typed total falls to about 596 MB against roughly 673 MB for the libyaml reference, with a 432 MB peak within 1.2x of 376 MB
- [x] the 1 MB typed total falls to about 60.4 MB and the 20 KB configuration total to about 703 KB
- [x] value and typed allocation budgets are tightened or pass, instruction counts pass, and both test modes plus conformance pass
