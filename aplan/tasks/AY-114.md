## Why

Three independent reviews of AY-110 to AY-113 found that two entry spans were still inexact, that
a plain number under a custom tag no longer read into a float, that the allocation gate and two
policy tests passed where they should fail, and that several figures in the docs and the
changelog were stale, wrong, or set beside a reference they couldn't be compared with. One timing
test failed on a busy host.

## Acceptance criteria

- [x] a key that is a block scalar takes no `:` from the line after it, so the entry around it has no span; a value's place is judged from its mapping's column, which a tag or an anchor before a key doesn't move; and an input with a byte-order mark past its first character gives no entry span
- [x] the span of a pair in a flow sequence ends with its value, and the rustdoc says where a scalar that isn't written stands and what an entry span can't answer for
- [x] the span tests compare events as well as values, in order, the generated documents include tags and anchors before keys, bare kind tags, anchors on collections, block-scalar keys, and byte-order marks, and of 85 single changes to the span code 74 fail a test, the rest being code that no input reaches
- [x] a plain scalar under a custom tag keeps the text a float target reads, as in 0.1.3, and a plain scalar whose text is not a slice of the source keeps its text
- [x] tests pin what a borrowing target and a float target read from a scalar that a core tag retypes, the room reserved for a root mapping, and that the room is not reserved again for its items; each fails under the single change it guards against
- [x] the allocation gate fails on a budget file that holds no row, which the check suite tests, and the policy tests require each of the gate's three calls on a line of its own, the gate in CI, and one call that runs the check suite
- [x] the timing test of nested keys tries again within a budget before it fails, with the bound it had, and the test of an input over the limit has its bound of 1 MiB back
- [x] the changelog and `docs/benchmarks.md` give the value path's figures against 0.1.3 as measured, the issue's references, and the figures of an untyped decode by the issue's measure; `docs/limits.md` gives the tokens' memory for tags with long names
- [x] the plan declares the two breaking changes, so the next version it gives is 0.2.0, and the 0.2 milestone waits for AY-104 (D94)
