## Why

Even with `#![forbid(unsafe_code)]` in `ayaml`, transitive dependencies and the
counting global allocator in `fuzz/src/bin/memcount.rs` rely on `unsafe` code.
Running a scoped Miri job checks for undefined behavior in those paths, and
expanding `tests/adversarial.rs` with newly reported YAML denial-of-service
shapes keeps resource defenses ahead of real-world attacks.

## Acceptance criteria

- [x] a scheduled workflow runs a bounded `cargo +nightly miri test` pass over core `ayaml` unit tests and allocator tests
- [x] `crates/ayaml/tests/adversarial.rs` adds `in_child!` regression tests covering deep flow collections, large single-line flow mappings, chained merge-and-alias inputs, oversized tag handles, repeated document-end markers, and duplicate-key collision stress
- [x] all new adversarial tests pass within the address-space and time bounds in debug and release builds
