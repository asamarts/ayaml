## Why

Once `1.0.0` ships, the public API, enum variants, error formatting, and crate dependency
requirements are locked for the entire `1.x` series. The pre-1.0 audit found several items
that must be resolved before freezing `1.0.0`:

1. **39 deprecated 0.x shims still present:** 39 `#[deprecated]` items across `emitter.rs`,
   `event_emitter.rs`, `lib.rs`, `span.rs` (`Marker`), `spanned.rs`, and `typed/doc_de.rs`
   explicitly state they will be removed in `1.0` (D104).
2. **`ayaml-edit` exact `=VERSION` dependency pin hazard:** `crates/ayaml-edit/Cargo.toml` and
   `tools/check_release.py` currently require `ayaml = "=VERSION"`. Publishing `ayaml-edit 1.0.0`
   with `ayaml = "=1.0.0"` would break Cargo dependency resolution whenever a downstream user
   upgrades `ayaml` to `1.0.1` or `1.1.0` without bumping `ayaml-edit`, even though `ayaml-edit`
   relies only on `ayaml`'s stable public API.
3. **Dead public enum variant `ErrorKind::Alias`:** `ErrorKind::Alias` is never constructed
   anywhere in the codebase (unknown anchors and cyclic aliases emit `ErrorKind::Composition`
   with `ErrorCode::UnknownAnchor` / `ErrorCode::CyclicAlias`). Freezing a dead variant in 1.0
   creates permanent API clutter unless intentionally resolved.
4. **Missing `#[non_exhaustive]` on `FrontmatterDelimiter` and minor freeze-test gaps:**
   `FrontmatterDelimiter` is the only public non-`Value` enum without `#[non_exhaustive]`,
   and `api_freeze.rs` does not yet pin `Sync`/`Copy`/`Debug` on `Emitter<'_>`, `Hash` on
   `Event<'_>`, `Clone` on `mapping::IntoIter`, or `Debug` on `Entry<'_>`. Also `Error::fmt`
   and `MaskedError::fmt` disagree slightly on when to print `at line L column C`.
5. **Pre-1.0 security policy:** `SECURITY.md` still states that only the latest `0.2.x`
   release receives security fixes and must transition to `1.x` alongside the `1.0.0` release.

## Scope

1. Remove all 39 deprecated 0.x shims (and any internal test/doc references), documenting each
   removal in `CHANGELOG.md` under `### Changed` / `### Removed` so `tools/check_public_api.py`
   accepts the intentional 1.0 break.
2. Update `crates/ayaml-edit/Cargo.toml`, `tools/check_release.py`, `RELEASING.md`, and
   `crates/ayaml/tests/repository_policy.rs` so `1.x` releases pin `ayaml = "^MAJOR.MINOR.PATCH"`
   (or `^1.0.0` at 1.0.0) while keeping `0.x` exact-pin discipline only for pre-1.0 versions.
3. Remove dead `ErrorKind::Alias` and add `#[non_exhaustive]` to `FrontmatterDelimiter`,
   recording the 1.0 API surface decisions in `docs/decisions.md` and syncing
   `docs/error-codes.md` and `crates/ayaml/tests/contracts/core.rs`.
4. Align `Error::fmt` vs `MaskedError::fmt` location printing, close the remaining
   `api_freeze.rs` trait assertions, and prepare the `SECURITY.md` `1.x` support-policy update
   for the `1.0.0` version bump.

## Acceptance criteria

- [ ] zero `#[deprecated]` 0.x shims remain in `crates/ayaml/src/` and `crates/ayaml-edit/src/`
- [ ] `tools/check_release.py` and `RELEASING.md` support SemVer caret requirements (`^1.0.0`) for `ayaml-edit` -> `ayaml` in `1.x` releases
- [ ] dead `ErrorKind::Alias` is removed, `FrontmatterDelimiter` is `#[non_exhaustive]`, `Error::fmt`/`MaskedError::fmt` location formatting is consistent, and all `api_freeze.rs` trait assertions pass
- [ ] `tools/check_public_api.py`, `cargo-semver-checks` (where applicable), `book_doctests`, and `repository_policy` pass cleanly
