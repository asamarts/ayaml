## Why

Published 1.0 benchmark comparisons must be completely fair, reproducible, accurate, and fresh
on the `1.0.0` release candidate commit. The adversarial audit identified several issues in
the current snapshot and site presentation:

1. **Three comparative harness fairness bugs:**
   - The `libyaml` memory shim loads only 1 of 49 documents on `cluster-manifests` (whereas its
     speed benchmark loads all 49), artificially lowering `libyaml load` memory ratios.
   - The `fkYAML` speed shim runs an unshared recursive `count_nodes(root)` traversal inside
     the timed closure, penalizing `fkYAML` relative to peers that only build and drop a DOM.
   - `ayaml events` benchmarks `#[doc(hidden)] ayaml::internals::parse_events` (eager
     `Vec<Event>`) instead of the public pull-based `ayaml::parse_events(input)` cursor, while
     `site/src/pages/benchmarks.astro` describes it as the pull-based event stream.
2. **Factual mislabeling and selective omission on `large-scalar-1mb`:**
   - `large-scalar-1mb` is a single-line plain scalar (`"x".repeat(1_000_000) + "\n"`), not a
     literal/folded block scalar, yet `bench.ts` and `benchmarks.astro` call it `"1 MiB block scalar"`.
   - The KPI highlight omits that `libfyaml events` reaches `1,576 MiB/s` on `large-scalar-1mb`
     and that `large-scalar-1mb` accounts for over half the headline geomean gap vs `libyaml events`.
3. **Missing reproducibility metadata and semantic caveats (D105):**
   - `/benchmarks/` and `docs/benchmarks.md` omit exact peer crate and C/C++ library versions,
     Rust and C/C++ compiler/LTO flags, Criterion settings (`warm_up`, `measurement`,
     `sample_size`, `rounds`), the `serde-saphyr` -> `serde_json::Value` target difference,
     per-peer scenario exclusions, duplicate-key / insertion-order semantic differences across
     parsers, the synthetic-fixture caveat, and CPU microarchitecture generation.
4. **Missing scaling/emit rows and stale commit:**
   - `speed.jsonl` omits 1 MiB timed scaling (`scale-{map,seq,openapi}-1mb`), `memory.jsonl`
     omits `emit`, and `fingerprint.json` still pins an older commit predating 14+ commits in
     `crates/ayaml/src` and the `AY-169..AY-173` fixes.

## Scope

1. **Fix comparative harness fairness and completeness:**
   - Fix `libyaml` memory measurement to load all documents on multi-document inputs.
   - Remove the unshared post-parse `count_nodes(root)` walk from timed `fkYAML` parsing.
   - Benchmark the public pull-based `ayaml::parse_events(input)` API cleanly (matching the
     copy on `/benchmarks/`), and add `scale-{map,seq,openapi}-1mb` timed rows + `emit` memory
     rows + `noyalib borrowed` on `boundary-4kb-*` where supported.
   - Export `fixture_manifest_sha256` from `ayaml_fixtures::manifest().manifest_sha256` and
     record exact peer versions, compiler/LTO flags, Criterion settings, and CPU microarchitecture
     class in `fingerprint.json`.
2. **Publish clean standalone comparative benchmark harness (`asamarts/ayaml-benchmarks`):**
   - Publish a standalone, sanitized comparative harness repository outside `asamarts/ayaml`
     so the main repository remains 100% pure Rust while external engineers can inspect and
     re-run every peer comparison end-to-end.
   - Pin the published comparative harness commit SHA, exact peer versions, Rust and C/C++
     compiler/LTO flags, and Criterion settings in `site/src/data/benchmarks/fingerprint.json`.
3. **Fix copy accuracy and full methodology disclosure (`site/src/lib/bench.ts`, `benchmarks.astro`, `index.astro`, `docs/benchmarks.md`):**
   - Rename `"1 MiB block scalar"` -> `"1 MiB plain scalar"` and present `large-scalar-1mb`
     honestly alongside `libfyaml events`.
   - Add a compact, verifiable Environment & Peer Versions section (harness repository link +
     pinned SHA, exact peer versions, build flags, Criterion parameters, `serde-saphyr` ->
     `serde_json::Value` caveat, per-peer excluded scenarios, duplicate-key/insertion-order
     semantics, and synthetic-fixture note).
   - Distinguish cleanly between what `cargo xtask` reproduces (all `ayaml` benchmarks and the
     `ayaml-fixtures` catalog) and the standalone comparative peer harness.
4. **Capture primary 1.0 benchmark snapshot on modern dedicated/bare-metal Linux hardware:**
   - Re-run both the `v0.2.3` baseline and the `1.0.0` release candidate on the same modern
     dedicated-CPU or bare-metal `x86_64` Linux host (`rounds >= 3`, recording full CPU
     microarchitecture class and variance/CV metrics; plus an optional ARM64 verification run).
   - Refresh `site/src/data/benchmarks/{fingerprint.json,speed.jsonl,memory.jsonl,v023-speed.jsonl,v023-memory.jsonl}`
     and update all derived site metrics and charts cleanly.
