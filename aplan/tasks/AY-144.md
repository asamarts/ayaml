## Why

Callers reading YAML from files, pipes, or network streams expect bounded
`from_reader` entry points, and `from_str` / `from_slice` / `from_slice_borrowed`
currently lack matching `_with_limits` variants on the root API.

## Acceptance criteria

- [x] `from_reader` and `from_reader_with_limits` read at most `max_input_bytes + 1` bytes before failing with `ErrorKind::Limit`, preventing unbounded reads from hostile streams
- [x] `from_str_with_limits`, `from_slice_with_limits`, and `from_slice_borrowed_with_limits` complete the root reader symmetry (checking input size before UTF-8 validation)
- [x] unit and `in_child!` adversarial tests verify bounded reader rejection on infinite and oversized streams as well as I/O error propagation
