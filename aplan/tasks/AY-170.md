## Why

The pre-1.0 correctness audit uncovered four semantic edge cases across merge keys,
`ayaml-edit`, and `ayaml::compat`:

1. **Core collection tag mismatch in `merge/events.rs`:** `Tag::is_core_collection()` treats
   `!!set`, `!!omap`, and `!!pairs` as core collection tags (matching `composer.rs`), whereas
   `merge/events.rs` only recognizes `!!map` and `!!seq`. This causes `ParseOptions::with_merge_keys(true)`
   and `Value::apply_merge_keys()` to disagree on tagged merge operands and complex keys.
2. **Complex mapping keys skipped in `Value::apply_merge_keys`:** `crates/ayaml/src/merge.rs`
   recurses into mapping values but skips complex mapping keys, diverging from
   `ParseOptions::with_merge_keys(true)` and omitting `max_depth` enforcement inside complex keys.
3. **`ayaml-edit` event-verification DP/fallback bugs and pre-limit output allocation:**
   - The event-verification DP in `crates/ayaml-edit/src/lib.rs` collapses Pareto-incomparable
     `(removals_used, replaces_used)` states into a single lexicographic minimum, causing
     false `VerificationFailed` rejections on valid multi-op batches.
   - Its greedy fallback (triggered when the DP table exceeds 1,000,000 cells) prioritizes
     deletions ahead of scalar replacements, rejecting valid large batches where a replacement
     precedes a removal.
   - `apply_edits` allocates the entire spliced output string before checking
     `options.parse.limits.max_input_bytes`, and `EditError` interpolates unmasked parser errors
     into `VerificationFailed` without providing a `masked()` view.
4. **`compat::map_error` drops `LimitExceeded` metadata:** When translating `DepthLimit` and
   `DocumentCountLimit` errors in `crates/ayaml/src/lib.rs`, `compat::map_error` omits
   `.with_limit(...)`, leaving `err.limit()` as `None` even when `err.code()` names a limit.

## Scope

1. **Unify core collection tag handling in `crates/ayaml/src/merge/events.rs`:**
   - Delegate to `Tag::is_core_collection()` / `Tag::is_core_scalar()` so `!!set`, `!!omap`,
     and `!!pairs` behave identically across event-layer and `Value`-layer merge keys.
2. **Recurse into complex mapping keys in `crates/ayaml/src/merge.rs`:**
   - Process complex keys during `Value::apply_merge_keys` / `apply_merge_keys_with_limits`
     with full `max_depth` enforcement and duplicate-key checks, ensuring parity with
     `ParseOptions::with_merge_keys(true)`.
3. **Harden `crates/ayaml-edit/src/lib.rs`:**
   - Fix the event verifier so Pareto-distinct `(removals_used, replaces_used)` states are
     preserved and the large-batch fallback handles mixed replacement/removal ordering cleanly.
   - Compute the exact spliced output length before allocation and fail fast when it exceeds
     `options.parse.limits.max_input_bytes`.
   - Avoid leaking raw document text through `VerificationFailed` diagnostics and add
     `EditError::masked()` (or equivalent redaction consistent with `ayaml::Error::masked()`).
4. **Preserve limit metadata in `compat::map_error` (`crates/ayaml/src/lib.rs`):**
   - Retain `.with_limit(limit)` on translated `DepthLimit` and `DocumentCountLimit` errors
     while keeping `compat` error messages intact.
5. **Regression tests:** Add targeted unit and integration tests for every fixed edge case.

## Acceptance criteria

- [x] `!!set`, `!!omap`, `!!pairs`, and complex-key merges produce identical results between `ParseOptions::with_merge_keys(true)` and `Value::apply_merge_keys()`
- [x] `ayaml-edit` passes targeted regression tests for mixed `ReplaceScalar` + `RemoveEntry` batches (both DP and large-batch paths), pre-allocation `max_input_bytes` enforcement, and masked error output
- [x] `compat::map_error` preserves `Error::limit()` on translated `DepthLimit` and `DocumentCountLimit` errors
- [x] full workspace tests, `--cfg ayaml_typed_from_events`, and `ayaml-edit` API/Miri/Kani checks pass
