## Why

Issues #160, #161, and #162 report the three common cases where a diagnostic named the rule that
failed instead of the collection, quote, or value the user has to fix.

## Acceptance criteria

- [x] a compatibility indentation mistake names the collection whose indentation it breaks
- [x] an unclosed quoted scalar names the opening quote
- [x] Serde `invalid_type` errors carry the actual unexpected value on the value and event paths
- [x] real trailing content still reports `unexpected content after document`
