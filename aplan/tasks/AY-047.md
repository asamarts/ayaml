## Why

Error text can include values from the document, and callers who log errors from
untrusted or sensitive files have no way to exclude them. adotenv offers `masked()` for
the same reason.

## Acceptance criteria

- [x] `Error::masked()` returns a wrapper whose `Display` and `Debug` hold no document text, showing kind, code, and location
- [x] a test passes a marker value through every error path that can carry one and asserts it is absent
- [x] documentation states that normal `Display` may include document text, and when to use the masked form
