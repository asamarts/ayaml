## Why

`Value::apply_merge_keys` currently recurses through arbitrary `Value` trees
without a depth guard, performs a redundant map lookup before inserting each
merged entry, and lacks bounded adversarial tests for chained and wide merge
patterns. Callers constructing or combining `Value` trees programmatically should
never hit a stack overflow, and merge behavior should stay bounded and linear.

## Acceptance criteria

- [x] `Value::apply_merge_keys` enforces a recursion depth limit (returning `ErrorKind::Limit`) and exposes a `_with_limits` form when callers need custom bounds
- [x] merged entry insertion avoids double hashing while preserving own-key precedence and key order
- [x] `crates/ayaml/tests/adversarial.rs` covers deep, wide, and chained merge patterns inside `in_child!`
- [x] `docs/limits.md` documents the merge-key recursion bound
