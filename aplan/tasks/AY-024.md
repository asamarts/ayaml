## Why

Valid forms fail on 0.1.0 and 0.1.1, some in common hand-written files.

## Acceptance criteria

- [ ] a tab after `key:` before a quoted or flow value, and after a quoted value before a comment, parses
- [ ] a plain scalar's continuation line that starts with `---` or `...` parses unless it is a document marker: at column 0, followed by whitespace or the end of the line
- [ ] a plain scalar's continuation line of `|` or `>` before a comment parses
- [ ] a top-level multi-line quoted scalar that starts past column 0 accepts continuation lines at any indent
- [ ] a comment after a `%TAG` directive parses
- [ ] a BOM before a multi-line quoted scalar parses
- [ ] tagged scalars and sequences decode into plain targets where the tag does not change meaning
- [ ] a defaulted struct variant accepts its bare tag form
- [ ] `&str` and `Cow` targets borrow plain scalars followed by a comment
