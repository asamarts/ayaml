## Why

Valid forms fail on 0.1.0 and 0.1.1, some in common hand-written files.

## Acceptance criteria

- [ ] a tab after `key:` before a flow collection, or before a quoted value holding a colon, parses, as does a tab after a quoted value before a comment holding a colon
- [ ] a plain scalar's continuation line that starts with `---` or `...` parses unless it is a document marker: at column 0, followed by whitespace or the end of the line. In compat, `...` followed by a byte order mark isn't a marker either, as libyaml reads it after a line that holds a paragraph separator
- [ ] a plain scalar's continuation line before a comment holding a colon parses, because a comment's colon is not a mapping indicator
- [ ] in default mode, a plain scalar after a node property that ends in `:` may go on at its own line's indentation when the node starts its line or follows `---`, as it may in compat. Default mode ends the scalar at its first line there and refuses the next
- [ ] a tab before `:` after a quoted key, an alias, or a node property, between a node property and a key or a flow collection, or before a flow collection on a `---` line, parses
- [ ] a tab parses where the only later `: ` on its line is in a comment, whatever comes before the tab
- [ ] a tab after `---` before a single- or double-quoted scalar that holds `: ` parses, as a space there does. Before a block scalar header the header is judged on its own, so a header followed by a comment with no blank before it reports that comment, as it does after a space, not the tab
- [ ] a tab after a `-` indicator, or at the start of a line, before a flow collection, a quoted scalar, or a comment holding a colon parses where the grammar allows it
- [ ] a quoted scalar or flow collection on its own line under a block collection may continue at the collection's indent plus one, whatever the indent of the line that opened it
- [x] a top-level flow collection's lines, and those of a top-level quoted scalar with a tag or anchor, may be indented with tabs alone
- [x] a top-level multi-line quoted scalar that starts past column 0 accepts continuation lines at any indent
- [ ] a comment after a `%TAG` directive parses
- [ ] a closing quote on a line indented only with tabs parses, as a closing `]` or `}` there does
- [x] a collection nested in a top-level flow collection may continue at column 0, as the top-level collection's own entries may, in default mode as in compat
- [x] a quoted scalar in a top-level flow collection may continue at column 0
- [x] in compat mode, an anchor or alias name in a flow collection may hold a `:` followed by more text, as it may in default mode
- [x] a document prefix may repeat its byte order mark, as the stream grammar allows
- [x] a block collection after a byte order mark on a later line of the stream parses, because the mark takes up no column
- [x] a BOM before a multi-line quoted scalar, or before a comment and then an indented multi-line plain scalar, parses
- [ ] tagged scalars and sequences decode into plain targets where the tag does not change meaning
- [ ] a defaulted struct variant accepts its bare tag form
- [ ] `&str` and `Cow` targets borrow plain scalars followed by a comment
