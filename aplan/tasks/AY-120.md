## Why

`Mapping`'s three `IntoIterator` implementations name `indexmap`'s iterator types as their
`IntoIter`. That makes `indexmap`'s major version part of ayaml's public API: a new one would be
a breaking change here that nothing in this crate chose. AY-044 planned types of ayaml's own for
the next minor release, since replacing an associated type is a break, and D90 puts every break
that is already decided into 0.2.0.

## Acceptance criteria

- [x] `Mapping`, `&Mapping`, and `&mut Mapping` iterate through types this crate defines, which name no type of `indexmap`
- [x] those types keep what a caller could do with the old ones: iterate from both ends, know their length, clone the two that could be cloned, make an empty one, and print with `Debug`; the `indexmap` requirement becomes 2.6.0, the first release whose owning iterator can be cloned
- [x] `iter`, `iter_mut`, `keys`, `values`, and `values_mut` keep their signatures
- [x] no public item, associated type, or trait implementation of the crate names a type of `indexmap`, which a test of the sources shows
- [x] the changelog says what a caller that named the old types has to change
