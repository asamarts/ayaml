## Why

Changes made since 0.1.3 let three limits slip, on code that is in no release. A typed reader
indexed every line of an input over `max_input_bytes` to place the error, so the limit no longer
bounded its work. The token arena was reserved once from the density of the first tokens, up to
half the input's length, whatever `max_events` allowed and however sparse the rest of the input
was. And `max_scalar_bytes` skipped a scalar whose value is empty, though its text can be long.

## Acceptance criteria

- [x] a typed reader refuses an input over `max_input_bytes` at its start, without indexing its lines
- [x] the token arena reserves no more tokens than `max_events` allows, and no more than eight times the tokens already scanned
- [x] a root flow collection reserves room only for entries with content, up to `max_collection_entries`, on whichever line it opens
- [x] `max_scalar_bytes` counts the text of a scalar whose value is empty
- [x] every limit case gives the same answer after 4 KiB and 8 KiB of comments, where a typed reader takes another path
- [x] no allocation budget rises; of the nine #178 shapes five peak 1% to 21% lower and none more than 0.3% higher
- [x] `docs/limits.md` states the token size and the arena's bounds
