## Why

In compatibility mode, an unseparated flow `?` followed by `!` starts an explicit key and tag,
whereas default mode reads `?!...` as a plain scalar. Previously compat only treated `!@!` (via
`AY-080`) and bare `[?!!!,]` (via `AY-067`) as libyaml-style tags there, rejecting other non-word
local tags such as `[?!)!,]` and secondary-handle suffixes holding `!` such as `[?!!a!b,]` even
though both default mode and libyaml accept them.

## Acceptance criteria

- [x] after an unseparated flow `?` in compatibility mode, a tag whose characters before the second `!` contain any non-word character reads under the primary handle `!`, matching libyaml while still stopping at non-tag characters
- [x] after an unseparated flow `?` in compatibility mode, a secondary-handle (`!!`) tag suffix may hold `!`, matching libyaml for `[?!!!,]`, `[?!!a!b,]`, and `[?!!!!,]`
- [x] outside an unseparated flow `?`, `!.!` and `!!!` remain rejected as documented, and default mode continues to read `?!...` as a plain scalar
