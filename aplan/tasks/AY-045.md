## Why

Every event stores two markers with an eagerly computed line and column. That costs 48
bytes per span, and it is a cost on the hottest path. Consumers that want UTF-16 columns,
such as language servers, have to convert for themselves. adotenv stores byte ranges and
derives positions on demand, and ayaml takes the same shape.

## Acceptance criteria

- [x] first, a spike measures event size and the performance gates; if the gates fail, the design goes back for a decision
- [x] `Span` holds byte offsets, stays `Copy`, and converts to `Range<usize>`
- [x] `LineIndex`, `Position`, `PositionError`, and `ColumnEncoding` are public, with UTF-8, scalar, and UTF-16 columns
- [x] conversions return errors rather than clamping, and columns exclude a leading byte-order mark while offsets include it
- [x] `Error::location()` still returns a one-based line and column
- [x] the performance gates pass, and event size before and after is recorded
- [x] the changelog describes the migration
