## Why

DHAT profiling of typed and borrowed Serde decoding (`frontmatter-tiny`, `boundary-4kb-below`,
`boundary-4kb-above`, and `serde-value`) identified three structural overheads:

1. **4 KiB tree-fallback cliff (`typed.rs` `SMALL_INPUT_BYTES = 4096`):** Documents `<= 4 KiB`
   build an entire intermediate `typed::Node` tree (80 B/node + `Vec<(Node, Node)>` + per-map
   `HashSet<Cow>`) before Serde starts. On `boundary-4kb-below`, that tree accounts for
   **60.7% (`60.0 KiB`) of total peak heap** (`98.1 KiB` vs `59.8 KiB` just above 4 KiB), and
   on `frontmatter-tiny` it adds **+16 internal allocations** over streaming.
2. **Per-map `HashSet<Cow>` and `Node` / `VecDeque` bounce in `typed/stream.rs`:**
   `Open::Mapping` allocates a fresh `HashSet<SeenKey>` on every mapping (`~38,000` allocs on
   `scale-openapi-1mb serde-value`, `~4,375` on `openapi-spec`), even for 1-to-8-key mappings
   and even when deserializing directly into `Value` (whose `Mapping` already rejects duplicate
   keys!). Every scalar also passes through a 4.6 KiB `VecDeque<Event>` and constructs an 80 B
   `Node<'de>`.
3. **`SpannedTree::parse` buffering (`spanned.rs`):** `SpannedTree::parse` pulls events through
   `EventCursor` (materializing full events) and uses `HashMap<Value, usize>` duplicate-key
   checks even for simple string keys.

## Scope

1. **Stream typed Serde at all document sizes (`typed.rs`, `typed/stream.rs`):**
   - Remove the `SMALL_INPUT_BYTES = 4096` split so `from_str` and `from_str_borrowed` use the
     streaming deserializer directly from byte 0 (preserving exact document-order error
     precedence on the cold error fallback path).
2. **Eliminate per-map `HashSet` and scalar `Node` churn (`typed/stream.rs`, `serde_impl.rs`):**
   - Replace per-map `seen: HashSet<SeenKey>` with a shared flat stack of seen keys using
     linear comparison for `<= 8` keys (zero heap allocations per small map), promoting to a
     hash set only for mappings with `> 8` keys.
   - Bypass constructing 80 B `Node<'de>` wrappers on the direct scalar fast path (`deserialize_str`,
     `deserialize_string`, integers, floats, bools, identifiers) and skip redundant `seen`
     tracking when decoding into `ayaml::Value` (or route `from_str::<Value>` cleanly while
     preserving exact Serde contract).
   - Shrink `DocumentEvents`'s event queue / pull directly from the streaming parser from `AY-180`.
3. **Stream `SpannedTree::parse` directly (`spanned.rs`):**
   - Feed `SpannedTree::Builder` directly from `EventSink` without intermediate full-document
     event buffering and fast-path string-key duplicate checking.

## Acceptance criteria

- [x] `boundary-4kb-below` and `boundary-4kb-above` have smooth, cliff-free peak heap (both <= 35 KiB for `typed`/`borrowed`) and beat `serde-saphyr` on both peak heap and allocation count
- [x] `frontmatter-tiny` `typed` allocations drop from 35 to <= 18 and peak heap drops from 10.2 KiB to <= 3 KiB
- [x] `scale-openapi-1mb` `serde-value` allocations drop by >= 30,000 and `spanned` peak heap drops substantially
- [x] full workspace tests, `--cfg ayaml_typed_from_events` equivalence, YAML Test Suite, Miri, Kani, and Callgrind checks pass cleanly
