## Why

`parser.rs` is 3,729 lines and combines document/event driving, grammar states, arena handling,
diagnostics, and unit tests. These concerns need navigable module boundaries before more typed
correctness and performance work changes the same path.

## Acceptance criteria

- [ ] parser code is split by responsibility into ordinary Rust modules; `include!` and generated concatenation are not used to evade the line rule
- [ ] every resulting file is at most 2,000 lines, and the parser exclusion and temporary ratchet leave `.alint.yml`
- [ ] private visibility stays narrow, existing parser test names used by plan evidence still resolve, and no public API changes
- [ ] event order, spans, first errors, document laziness, compatibility behavior, and arena behavior are unchanged on the corpus, strict suites, adversarial tests, and fuzz smoke
- [ ] allocation and instruction gates show no regression attributable to the split, and no new allocation, copy, dynamic dispatch, or repeated computation is introduced
