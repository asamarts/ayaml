## Why

`scanner.rs` is 3,709 lines. Its tokenization, scalar handling, line walking, diagnostics,
and unit tests can have explicit module boundaries without changing the hot path or public API.

## Acceptance criteria

- [x] scanner code is split by responsibility into ordinary Rust modules; `include!` and generated concatenation are not used to evade the line rule
- [x] every resulting file is at most 2,000 lines, and the scanner exclusion and temporary ratchet leave `.alint.yml`
- [x] private visibility stays narrow, existing scanner test names used by plan evidence still resolve, and no public API changes
- [x] scanning order, token spans, first errors, compatibility behavior, and allocation behavior are unchanged on the corpus, strict suites, adversarial tests, and fuzz smoke
- [x] the allocation and instruction gates show no regression attributable to the split, and no new allocation, copy, dynamic dispatch, or repeated computation is introduced
