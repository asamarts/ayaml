## Why

The event writer can return success on input that does not produce valid YAML, and
empty collections are not charged for depth by the value writer.

Each of these turns a success into an error, for input that produced invalid YAML. The owner
decided on 2026-11-19 to ship it in 0.2.0, with the other changes that a caller can notice
(D97).

## Acceptance criteria

- [x] undefined and forward aliases are errors
- [x] invalid `%YAML` values, duplicate directives, and bad tag handles are errors
- [x] a hand-built `!!int`, `!!float`, `!!bool`, or `!!null` tag on a scalar that the tag's rule doesn't take is an error, before any of its document is written; a tag that a reader loads, as the value the tag makes of the text or with the tag dropped, is written as it was
- [x] nothing that a reader of the crate loads is newly refused: the writers before and after are compared on every stored fuzz input as each reader gives it
- [x] the value writer, event writer, and parser agree on depth for empty collections
