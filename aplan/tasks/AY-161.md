## Why

Teams adopting `ayaml` typically migrate from one of the top three existing
Rust YAML ecosystems (libyaml-backed Serde crates, pure-Rust YAML 1.2 DOM/event
crates, or pure-Rust YAML 1.2 Serde crates). Concrete side-by-side API tables,
behavioral caveats, and runnable examples remove migration friction.

## Acceptance criteria

- [x] three dedicated migration guides cover API mapping, YAML 1.2.2 vs 1.1 differences, duplicate keys, merge keys, spans/positions, limits, and `ayaml::compat` fallbacks
- [x] every Rust code snippet across all three migration guides compiles and passes through `book_doctests`
- [x] an end-to-end test suite verifies the documented behavioral edge cases and migration recipes
