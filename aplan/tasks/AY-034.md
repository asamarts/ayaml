## Why

`docs/limits.md` claims every check is tested just below, at, and above its limit.
Most limits are only tested far above, on one or two entry points, and several
reject-at-limit mutants survive.

AY-026 added `crates/ayaml/tests/limit_consistency.rs`: a table of inputs, each with the least
value of one limit that accepts it, run just below, at, and above that value on every reader that
takes limits. This task can extend it to each place that counts, and to the readers that take the
default limits only.

## Acceptance criteria

- [ ] a table-driven test covers each limit below, at, and above on each entry point where it applies
- [ ] the entry-count limit is covered at each place that counts entries: block and flow mappings, block and flow sequences, and explicit keys, including the short-block fast paths
- [ ] entries that cannot apply are stated as such in the table
- [ ] reject-at-limit mutants fail, with limit-disabling mutants excluded or run under a memory bound
- [ ] `docs/limits.md` describes what the table proves
