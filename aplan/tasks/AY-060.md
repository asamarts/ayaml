## Why

Indentation detection for block scalars treats some whitespace-only lines wrongly, in both
modes and in both directions: a scalar with no content lines can be rejected, and a line of
spaces and a tab can avoid the check on leading empty lines.

## Acceptance criteria

- [x] a whitespace-only line in a block scalar with no content lines isn't taken as its content, so the scalar is empty and the next node parses
- [x] a comment line at or below the parent's indent ends a block scalar that has only whitespace-only lines, so the scalar is empty
- [x] the check on leading empty lines measures against the first line with content, counting a tab after the indent as content
- [x] with an explicit indentation indicator, a line that holds a tab at or past the content indent is content, and it isn't read as a comment
- [x] a comment line that starts with a tab directly after a block scalar is rejected where the grammar allows no comment
- [x] by default, a root block scalar's indentation indicator counts from the root's indentation of -1, so `|1\n y\n` reads ` y\n` as productions 170 and 174 say; compat keeps libyaml's `y\n`, and a test covers both
- [x] suite classifications are unchanged or justified
- [x] the changelog names the changed behavior
