## Why

Indentation detection for block scalars treats some whitespace-only lines wrongly, in both
modes and in both directions: a scalar with no content lines can be rejected, and a line of
spaces and a tab can avoid the check on leading empty lines.

## Acceptance criteria

- [ ] a whitespace-only line in a block scalar with no content lines isn't taken as its content, so the scalar is empty and the next node parses
- [ ] a comment line at or below the parent's indent ends a block scalar that has only whitespace-only lines, so the scalar is empty
- [ ] the check on leading empty lines measures against the first line with content, counting a tab after the indent as content
- [ ] with an explicit indentation indicator, a line that holds a tab at or past the content indent is content, and it isn't read as a comment
- [ ] a comment line that starts with a tab directly after a block scalar is rejected where the grammar allows no comment
- [ ] suite classifications are unchanged or justified
- [ ] the changelog names the changed behavior
