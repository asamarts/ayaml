## Why

A review of AY-022 and AY-064 found statements that weren't true. The documentation said a marker
right after a byte order mark is still a marker, but `...` was an error there. The changelog said
compat keeps libyaml's reading of a mark because libyaml counts a column, but compat counted it
only for error positions, so a later line's block collection could read differently, with no
error. The changelog also said flow and quoted lines under a block collection always need
indentation, which isn't so, and a test called the rejection of a valid quoted scalar right.

## Acceptance criteria

- [x] a `...` after a byte order mark ends a document by default, as the stream grammar allows
- [x] in compat, a later line's byte order mark takes up a column for block structure, as it does for error positions
- [x] the compat chapter and the changelog state what the mark does, and the exceptions to the indentation rule
- [x] no test asserts the rejection of a quoted scalar that the grammar accepts
